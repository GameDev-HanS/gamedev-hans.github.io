변경사항을 **보안 검사 → 브라우저 테스트 → 커밋** 순서로 처리하고, 결과를 Discord로 알려 주세요.
두 검사를 모두 통과해야 커밋합니다. **푸시는 하지 않습니다.** 사용자가 GitHub Desktop에서 직접 합니다.

추가 요청: $ARGUMENTS

## 알림 규칙

이 명령어는 `-Type pipeline` 알림만 보냅니다. commit.md, test.md에 나오는 알림 명령(`-Type commit`, `-Type test`) 대신 항상 아래 명령을 씁니다.

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .claude/scripts/notify-discord.ps1 -Type pipeline -Status <passed|blocked|failed> -Step "<멈춘 단계>" -Detail "<요약>"
```

- 알림은 두 경우에만 보냅니다.
  - **중간에 멈출 때**: 멈춘 그 자리에서 바로 보냅니다. `-Step`에 `보안 검사`, `테스트`, `커밋` 중 하나를 적습니다.
  - **모두 끝났을 때**: `-Status passed`로 한 번 보냅니다. 이때 `-Step`은 넣지 않습니다.
- 알림을 보낸 뒤에는 사용자에게 바로 알리고 남은 단계를 멈춥니다.
- `-Status`: 위험 발견, 사용자 취소, 테스트 문제처럼 검사에 걸려 멈추면 `blocked`, 명령 오류나 서버가 안 뜨는 등 진행 자체가 안 되면 `failed`입니다.
- `-Detail`에는 비밀값, 개인정보, 폼 입력값을 넣지 않습니다.

## 1단계: 보안 검사

[commit.md](commit.md)의 "준비"와 절차 1~5를 그대로 따릅니다. 다른 점은 다음과 같습니다.
- 처음부터 변경사항이 없으면 알림 없이 끝냅니다.
- 위험 파일을 빼고 나니 스테이징된 파일이 하나도 없으면 `-Status blocked -Step "보안 검사" -Detail "커밋할 파일 없음"`으로 알리고 끝냅니다.
- `privacy-guard`의 결과가 **위험 있음**이면 AskUserQuestion으로 "위험 파일 제외 후 계속 / 그대로 계속 / 취소"를 묻습니다.
  - 취소: `-Status blocked -Step "보안 검사"`로 알리고 끝냅니다.
  - 제외: 그 파일을 스테이징에서 빼고 계속합니다. 제외한 파일은 작업 폴더에 남아 있어 테스트에는 포함된다는 점을 사용자에게 알립니다.
- 검사 에이전트가 실행되지 않거나 오류로 끝나면 `-Status failed -Step "보안 검사"`로 알리고 끝냅니다.
- 이 단계에서는 아직 커밋하지 않습니다. 커밋 계획과 메시지 초안만 정해 둡니다.

## 2단계: 브라우저 테스트

[test.md](test.md)의 1~4단계(서버 준비, 기본 테스트, 정리, 보고)를 따릅니다. 다른 점은 다음과 같습니다.
- 범위는 항상 "기본 테스트" 전체입니다.
- test.md 4단계의 "고칠지 사용자에게 묻기"와 5단계 Discord 알림은 건너뜁니다. 고칠지는 파이프라인이 끝나거나 멈춘 뒤에 묻습니다.
- 테스트 중에는 파일을 고치지 않습니다.

결과에 따라 이렇게 합니다.
- **통과**, 또는 **사소한 문제만 있음**: 3단계로 갑니다. 사소한 문제는 최종 알림과 보고에 참고로 적습니다.
- **심각하거나 보통인 문제가 있음**: 커밋하지 않습니다. `-Status blocked -Step "테스트"`로 알리고 문제 목록을 보고한 뒤 끝냅니다. 스테이징은 그대로 둡니다.
- **테스트 실패**(서버가 안 뜨거나 브라우저를 쓸 수 없음): `-Status failed -Step "테스트"`로 알리고 끝냅니다.

브라우저와 직접 띄운 개발 서버는 결과와 관계없이 정리합니다.

## 3단계: 커밋

먼저 보안 검사 뒤에 바뀐 파일이 없는지 확인합니다. `& $g diff --name-only`(작업 폴더와 스테이징 비교)에 커밋할 파일이 나오면 검사하지 않은 내용이 섞인 것입니다. 이때는 커밋하지 않고 `-Status blocked -Step "커밋" -Detail "보안 검사 후 바뀐 파일: <경로>"`로 알리고 끝냅니다. 사용자에게는 `/commit-test`를 다시 실행하라고 안내합니다.

바뀐 파일이 없으면 [commit.md](commit.md)의 절차 6을 따릅니다 (커밋 나누기, git 경로 따로 조회, 단독 명령으로 커밋, 훅의 gitleaks 검사와 사용자 승인). 커밋이 하나뿐이면 스테이징을 비우지 말고 지금 스테이징된 그대로 커밋합니다. 알림은 이렇게 바꿔 보냅니다.
- 훅이 비밀값을 찾아 막음: `-Status blocked -Step "커밋"`
- 사용자가 승인 창에서 거부함: `-Status blocked -Step "커밋" -Detail "사용자가 커밋을 취소함"`
- 그 밖의 오류: `-Status failed -Step "커밋"`
- 커밋이 여러 개일 때 중간에 멈추면 남은 커밋도 멈추고, 이미 만든 커밋의 해시를 `-Detail`에 적습니다.
- `--no-verify` 같은 우회 옵션은 쓰지 않습니다.

## 4단계: 완료 알림과 보고

1. 모든 커밋이 끝나면 `-Status passed`로 알림을 한 번 보냅니다. `-Detail`에는 다음을 적습니다.
   - 보안 검사 결과
   - 테스트 결과 (통과 수 / 전체 수, 사소한 문제 요약)
   - 커밋 개수와 각 제목
   - 제외한 파일이 있으면 `제외: <경로> (<이유>)`
2. 사용자에게 짧게 보고합니다.
   - 보안 검사 결과
   - 테스트 결과 (test.md의 보고 형식)
   - 커밋별 해시와 메시지
   - 제외한 파일
   - 알림을 보냈는지
3. 마지막 줄에 "GitHub Desktop에서 Push origin을 눌러 푸시하세요."라고 적습니다.
