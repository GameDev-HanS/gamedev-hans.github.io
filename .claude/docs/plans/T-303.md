# T-303 Supabase Storage 준비와 무료 플랜 한도 확인

> 승인일: 2026-11-14 · 로드맵: [ROADMAP](../ROADMAP.md)

## Context
영상(F008)은 Supabase Storage 공개 버킷 URL을 `<video>`로 재생한다. T-304(Video 컴포넌트)·T-305·T-311이 이 작업에 막혀 있다. 코드 변경 없이, 운영자가 버킷을 만들고 테스트 영상을 올리면 Claude가 재생·구간 이동을 확인하고 한도를 기록한다.

## 무료 플랜 한도 (2026-11-14 확인)
출처: supabase.com/pricing, docs/guides/platform/billing-faq, docs/guides/storage/uploads/file-limits

| 항목 | 무료 플랜 |
|------|-----------|
| 파일 저장 용량 | 1GB |
| 전송량(egress) | 월 5GB + cached egress 월 5GB (cached는 Storage 전용) |
| 파일 1개 최대 크기 | 50MB |
| 활성 프로젝트 | 2개 (일시 정지된 프로젝트는 세지 않음) |
| 일시 정지 | 1주일 동안 활동이 없으면 프로젝트 일시 정지 |
| 요금 | $0. 한도를 넘으면 알림 → 유예 기간 → 서비스 제한(402 오류 등), 다음 결제 주기에 풀림. 유예는 한 번뿐이고 다시 넘으면 바로 제한 |

- Range 요청(구간 이동) 지원은 문서에 없어 실제 URL로 확인한다.

## 영상 1개 권장 크기
- H.264 영상 + AAC 음성 MP4, 1080p 이하(블로그 본문 폭이면 720p로도 충분), `+faststart`(메타데이터를 파일 앞에 두어 바로 재생 시작)
- 1분당 약 10~15MB 목표, **최대 50MB**(업로드 한도). 1GB 저장이면 약 30MB 기준 30개 정도
- 전송량 5GB/월 ≈ 30MB 영상 약 170회 전체 재생. `preload="metadata"`(T-304)로 재생하지 않으면 거의 받지 않음
- 압축 예시 (ffmpeg 설치 시):
  ```powershell
  ffmpeg -i 원본.mp4 -vf "scale=-2:'min(1080,ih)'" -c:v libx264 -preset slow -crf 26 -c:a aac -b:a 128k -movflags +faststart 결과.mp4
  ```
  크기가 크면 `-crf` 값을 28~30으로 올리거나 `1080`을 `720`으로 낮춘다.

## 운영자 할 일 (순서)
1. supabase.com 가입(무료 Free 플랜) → **New project** (이름 자유, 지역은 Northeast Asia (Seoul) 권장, DB 비밀번호는 저장소·문서에 적지 않음)
2. 왼쪽 메뉴 **Storage** → **New bucket**
   - 이름: `videos`
   - **Public bucket** 켜기
   - (선택) 파일 크기 제한 50MB, 허용 MIME `video/mp4`
3. `videos` 버킷에 테스트 MP4(50MB 이하) 업로드
4. 올린 파일 → **Get URL**(공개 URL) 복사 → Claude에게 전달
   - 형식: `https://<project-ref>.supabase.co/storage/v1/object/public/videos/<파일 이름>`
   - **API 키(anon/service_role)·DB 비밀번호는 전달하지 않음** — 공개 URL만 있으면 됨
5. 브라우저에서 URL을 열어 재생과 구간 이동(재생 바 클릭)이 되는지 확인

## Claude 검증
- `curl -I <URL>` → 200, `Content-Type: video/mp4`
- `curl -r 0-1023 -I <URL>` → `206 Partial Content`, `Content-Range`, `Accept-Ranges: bytes`
- 결과는 아래 결정에 기록 (URL은 `<project-ref>`로 가려 적음)

## 결정
- 2026-11-14: 무료 프로젝트 일시 정지는 자동 접속 장치 없이, 정지되면 운영자가 대시보드에서 다시 켠다. 불편해지면 GitHub Actions 주기 접속(공개 URL만 사용) 추가를 검토한다.
- 2026-11-14: 요금 청구 없음 확인 — Free 플랜은 한도 초과 시 청구가 아니라 제한.
- 2026-11-14: 프로젝트 생성 설정 — Data API 끔, 새 테이블 자동 공개 끔, 자동 RLS 켬 (DB를 쓰지 않으므로). 버킷 `videos`: Public, 파일 크기 제한 50MB, MIME `video/mp4`. 업로드·삭제 RLS 정책은 만들지 않음(대시보드 업로드만 사용).
- 2026-11-14 연결 확인: `https://<project-ref>.supabase.co/storage/v1/object/public/videos/<없는 파일>` → `NoSuchKey`(Object not found), 없는 버킷 → `NoSuchBucket`. 공개 경로로 `videos` 버킷에 닿음. 재생·Range 확인은 테스트 영상 업로드 후.
- 2026-11-14: 파일 이름에 한글 불가 — `15연승.mp4` → `InvalidKey`. 영상 파일 이름은 영문·숫자·`-`·`_`만 쓴다 (T-311 작성 가이드에 넣기).
- 2026-11-14 영상 검증 (`videos/15_win_streak.mp4`, 약 24.4MB, Windows 게임 바 녹화):
  - HEAD → `200`, `Content-Type: video/mp4`, `Accept-Ranges: bytes`
  - `Range: bytes=0-1023` → `206 Partial Content`, `Content-Range: bytes 0-1023/25604394`; 중간 구간(1000000-1000999)도 `206` → 구간 이동 가능
  - 코덱 H.264(`avc1`), HEVC 아님 → 주요 브라우저 재생 가능
  - `moov`가 파일 앞에 없음(faststart 아님) → 브라우저가 Range로 파일 끝을 먼저 읽어 재생은 되지만 시작이 조금 늦을 수 있음. 실제 글용 영상은 ffmpeg `-movflags +faststart`로 저장 권장
  - `Cache-Control: private, no-cache`, `CF-Cache-Status: DYNAMIC` → CDN 캐시를 거의 쓰지 않아 재생량은 주로 일반 egress(월 5GB)로 계산된다고 본다
  - 운영자 브라우저 확인: 재생·구간 이동 정상 → T-303 완료 조건 충족
- 2026-11-14: 코드 변경이 없어 코드 리뷰는 생략.
