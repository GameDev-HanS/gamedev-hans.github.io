# T-122 페이지 전환 크로스페이드 (React `<ViewTransition>`)

> 승인일: 2026-11-12 · 로드맵: [ROADMAP](../ROADMAP.md)

## Context
- 단계 1의 남은 두 작업 중 하나(T-122·T-125). 사이트 안에서 이동할 때 본문이 툭 바뀌는 대신 이전 본문이 빠르게 흐려지고 새 본문이 부드럽게 나타나게 합니다. 헤더·푸터는 움직이지 않습니다.
- 확인한 것: React 19.3.1, `@types/react` 19.3.0에 `ViewTransition` 타입이 있음(index.d.ts:2095) → tsc 문제 없음. Next 16.4.5 가이드(`node_modules/next/dist/docs/01-app/02-guides/view-transitions.md`): 설정·실험 플래그 불필요, 내비게이션은 transition이라 자동으로 동작, 미지원 브라우저는 애니메이션 없이 정상 이동.
- 코드에 `startTransition`·`Suspense`·`view-transition` 사용처 없음 → 겹치는 것 없음.

## 래퍼 위치 (로드맵 ⑧과 다르게 함)
로드맵에는 "각 page.tsx에 `PageTransition`을 감싼다"라고 되어 있지만, **레이아웃의 `<main>` 안쪽에 한 번만** 감쌉니다.
- 가이드가 page.tsx에 두라고 한 이유는 enter/exit(방향 슬라이드)가 레이아웃에서는 안 일어나기 때문입니다. 크로스페이드는 **update**(안쪽 DOM이 바뀔 때) 애니메이션으로 충분하고, 이건 레이아웃에서도 일어납니다.
- 장점: 파일 하나만 바꾸면 되고, 앞으로 생길 페이지(소개·태그 등)를 따로 감쌀 필요가 없습니다. `/games` → `/games/2026`, `/blog` → `/blog/글`처럼 같은 상위 경로 안에서 이동해도 똑같이 동작합니다. (`app/template.tsx`는 첫 경로 조각이 같으면 다시 마운트되지 않아 이 경우를 놓치므로 쓰지 않습니다.)
- 검증에서 update 크로스페이드가 안 나오면 계획대로 page마다 감싸는 방식으로 바꾸고 `## 결정`에 적습니다.

## 구현
1. **`components/shared/page-transition.tsx`** (새 파일, 서버 컴포넌트 가능)
   - `import { ViewTransition } from "react"` → `<ViewTransition default="page-fade">{children}</ViewTransition>`
   - 주석: 왜 레이아웃 한 곳에 두는지, update 크로스페이드라는 점
2. **[app/layout.tsx](../../../app/layout.tsx)**: `<main ...><PageTransition>{children}</PageTransition></main>`. Provider(음악·Motion·테마)는 래퍼 바깥이라 음악이 끊기지 않음
3. **site-header.tsx**·**site-footer.tsx**: `style={{ viewTransitionName: "site-header" }}` / `"site-footer"`
4. **app/globals.css** (기존 `@layer base` 근처에 한 묶음, 한국어 주석)
   - `:root`에 `--vt-exit: 150ms; --vt-enter: 210ms`
   - `::view-transition-old(.page-fade)`: `var(--vt-exit) ease-in both vt-fade reverse`
   - `::view-transition-new(.page-fade)`: `var(--vt-enter) ease-out var(--vt-exit) both vt-fade` (퇴장이 끝난 뒤 등장)
   - `::view-transition-group(.page-fade) { animation: none; }` — 페이지 높이 차이로 본문이 늘어나 보이는 것 방지
   - `@keyframes vt-fade { from { opacity: 0 } to { opacity: 1 } }` — PRD 규칙대로 투명도만(가이드의 blur는 쓰지 않음)
   - 헤더·푸터: `::view-transition-group(site-header|site-footer) { animation: none; z-index: 100 }`, `-old(...) { display: none }`, `-new(...) { animation: none }`
   - `::view-transition { pointer-events: none; }`
   - `@media (prefers-reduced-motion: reduce)`: `::view-transition-old/new/group(*)`에 `animation-duration: 0s !important; animation-delay: 0s !important`
- Motion은 본문 전체에 쓰지 않음(기존 Stagger/Reveal은 섹션 단위라 그대로 둠).

## 검증
1. `npm run lint`, `npx tsc --noEmit`, `npm run build`
2. 개발 서버 + Playwright (run_code 한두 번)
   - 헤더 메뉴·카드 링크로 이동할 때 `document.startViewTransition`이 호출되는지(훅으로 감지)와 `::view-transition-old/new` 애니메이션 이름·시간을 `document.getAnimations()`로 확인 (old 150ms, new 210ms + delay 150ms)
   - 헤더·푸터 그룹에 애니메이션이 없음, `/games` → `/games/2026`, `/blog` → 글 이동도 전환됨
   - 동작 줄이기 에뮬레이션에서 duration 0
   - 전환 직후 클릭 정상, 음악 버튼이 이동 뒤에도 상태 유지(음원이 없으면 생략)
   - 375px 넘침 없음, 콘솔 오류 없음
3. 리뷰 → 문서(product-manager 한 번) → `/commit-test`

## 결정
- 2026-11-12: 래퍼는 레이아웃 `<main>` 안 한 곳(update 크로스페이드)으로 확정 — 헤더 메뉴, `/blog`→글, `/games`→`/games/2026` 모두 전환됨을 확인
- 2026-11-12: `PageTransition`은 클라이언트 컴포넌트로, 하이드레이션 전에는 `update="none"`, 뒤에는 `"page-fade"` (`useSyncExternalStore`). 이유: 서버 HTML에 전환 속성이 있으면 첫 접속 때 React가 로딩 화면(app/loading.tsx) → 본문 교체에도 `startViewTransition`을 걸고 글꼴·화면 안 이미지를 기다려 본문이 늦게 보임. 첫 접속과 사이트 안 이동은 둘 다 transition type이 없어 CSS·props로는 구분 불가
- 2026-11-12: 위 결정이 "구현" 1번(서버 컴포넌트, `default="page-fade"`)을 대체함 — 실제는 클라이언트 컴포넌트, `update`만 쓰고 `default="none"`
- 2026-11-12: 참고 — 하이드레이션 뒤 `<main>` 안에서 `startTransition`으로 DOM을 바꾸면 본문 전체에 page-fade가 재생됨. 나중에 본문 안 상태 변경에 transition을 쓰면 확인 필요 (리뷰 지적)
- 2026-11-12: 가이드의 blur는 빼고 투명도만 (PRD 규칙). 본문 상자 크기 변화 애니메이션(`::view-transition-group(.page-fade)`)도 끔
- 2026-11-13: `app/loading.tsx`를 제거함 (Windows 빌드에서 세그먼트 프리페치 파일 이름 문제로 이동 때 회색 스켈레톤이 끼어 보였음 — 자세한 내용은 [plans/T-204.md](T-204.md) `## 결정`). 위 2026-11-12 항목의 '로딩 화면 → 본문 교체'는 지금은 해당 없음. 하이드레이션 전 `update="none"` 처리는 그대로 유지.
