# T-108 MDX 방식 확정 (스파이크)

> 승인일: 2026-11-09 · 로드맵: [ROADMAP](../ROADMAP.md)

## Context
- 블로그 글 기능의 기반. 공식 가이드(`node_modules/next/dist/docs/01-app/02-guides/mdx.md`) 방식이 이 프로젝트(Next.js 16, Turbopack, `output: "export"`)에서 실제로 빌드되는지 확인하고 frontmatter 처리 방식을 하나로 정한다.
- 가이드 핵심: `@next/mdx` + 루트 `mdx-components.tsx`(필수) + 동적 import + `generateStaticParams` + `dynamicParams = false`. frontmatter 기본 미지원. Turbopack에서는 remark/rehype 플러그인을 문자열 이름 + 직렬화 가능한 옵션으로만 지정.

## frontmatter 방식: YAML frontmatter
- 글 맨 위 YAML(`title`, `date`, `summary`, `tags` …). `export const metadata`(JS 문법)보다 쓰기 쉬움
- 본문에 YAML이 찍히지 않게 `remark-frontmatter`를 문자열 플러그인으로 등록
- 목록·메타데이터 읽기는 서버에서 `gray-matter` (T-109에서 본격 사용)
- GFM(표·취소선)용 `remark-gfm`도 문자열 플러그인으로 등록

## 변경
- 패키지: `@next/mdx @mdx-js/loader @mdx-js/react @types/mdx remark-frontmatter remark-gfm gray-matter`
- `next.config.ts`: `createMDX`로 감쌈, 기존 설정 유지, `pageExtensions` 추가 안 함
- 루트 `mdx-components.tsx`, 샘플 `content/posts/hello-world.mdx`
- 스파이크용 `app/blog/[slug]/page.tsx` (T-112에서 본격 구현)
- 막히면 next-mdx-remote(RSC) → Velite 순으로 시험

## 결과 (2026-11-09) — 공식 방식(@next/mdx)으로 확정, 대안 시험 불필요
- 설치 버전: `@next/mdx` 16.4.5, `@mdx-js/loader`·`@mdx-js/react` 3.1.1, `@types/mdx` 2.0.14, `remark-frontmatter` 5.0.0, `remark-gfm` 4.0.1, `gray-matter` 4.0.3
  - `npm install`에 peerDependencies 경고 없음 (low 취약점 3건은 기존 것, CI 기준 high 미만)
- `npm run build` 통과, Turbopack에서 문자열 플러그인 정상 동작. 라우트 `● /blog/hello-world` (SSG)
- `out/blog/hello-world.html`: 제목은 frontmatter `title`, 본문 `<h2>`·`<strong>`·목록·`<table>`(GFM) 정상, YAML 원문·구분선(`<hr>`) 미노출
- 없는 slug(`out/blog/nope.html`) 생성 안 됨 → `dynamicParams = false`로 404
- 기존 설정(`output: "export"`, `basePath`, `images.unoptimized`, Turbopack CSS 규칙) 유지된 채 빌드됨
- 참고: 새 경로를 추가하면 `PageProps<"/blog/[slug]">` 같은 경로 타입이 빌드(또는 `npx next typegen`) 전까지 없어 `tsc`가 실패함. 경로 추가 후에는 `npx next typegen` → `npx tsc --noEmit` 순서로 실행

## 리뷰 메모 (T-109로 넘김)
- 리뷰 결과 문제 없음. 다음은 로더(T-109)에서 처리:
  - frontmatter `title`이 없으면 스파이크 페이지에 "undefined"가 보임 → zod 검증으로 빌드 실패 처리
  - `content/posts/` 폴더가 없거나 글이 0개일 때 동작(빌드 중단·정적 내보내기 실패 여부) 확인
  - `@types/mdx`가 dependencies에 있음 (공식 가이드 설치 명령 그대로, 동작 영향 없음) — 필요하면 devDependencies로 이동

## 검증
- `npm install` 경고 없음, lint·tsc·build 통과
- `out/blog/hello-world.html` 생성, 본문 HTML 있음, YAML 글자 미노출, 제목은 frontmatter 값
- 없는 slug는 빌드 결과에 없음
