# T-306 태그 집계와 한글 표시 이름 대응표

> 승인일: 2026-11-13 · 로드맵: [ROADMAP](../ROADMAP.md)

## Context
글 태그는 URL용 영문 slug만 frontmatter에 쓰고(결정됨), 화면에 보일 한글 이름은 `content/tags.json` 대응표에서 가져오기로 했다. 지금은 글 카드·글 상세 칩이 `#blog`처럼 slug를 그대로 보여 준다. 이번 작업으로 대응표·로더·태그 집계(`getAllTags()`)를 만들고, 사용자 결정에 따라 기존 카드·상세 칩도 한글 이름으로 바꾼다. 태그 칩 링크·`/blog` 상단 태그 목록은 T-307, 태그 페이지(`out/blog/tags/shader`)는 T-308에서 한다.

## 사용자 결정 (플랜 단계)
- 범위: 로더 + 기존 글 카드·글 상세 칩을 한글 이름으로 (링크 연결은 T-307)
- 대응표 처음 값: `blog`→블로그, `devlog`→개발 일지, `shader`→셰이더, `hello-world.mdx`에 `shader` 태그 추가

## 변경
1. **`content/tags.json`** (새 파일): `{ "blog": "블로그", "devlog": "개발 일지", "shader": "셰이더" }`
2. **lib/posts.ts**
   - `tags.json` 스키마: `z.record(z.string().regex(SLUG, SLUG_MESSAGE), z.string().trim().min(1, ...))` — 키가 slug 형식이 아니거나 이름이 비면 `content/tags.json: ...` 메시지로 빌드 실패. JSON 형식 오류·BOM 처리는 `lib/content.ts`의 `readJson`과 같은 방식(`formatIssues` 재사용). 파일이 없으면 빈 대응표(모든 태그가 slug 그대로 표시).
   - `getTagLabels()` (React `cache`): 대응표를 한 번만 읽음.
   - `Tag = { slug: string; label: string }` 타입 추가, `Post.tags`를 `string[]` → `Tag[]`로 바꿔 `readPost`에서 label을 붙임 (대응표에 없으면 slug).
   - `getAllTags(): (Tag & { count: number })[]` — 모든 글의 태그를 세어 글 수 내림차순, 같으면 slug순.
   - 대응표에 있지만 글에 안 쓰인 태그는 오류 아님(미리 넣어 둘 수 있음).
3. **components/shared/post-card.tsx**, **components/sections/post-header.tsx**: `#{tag.label}`, key는 `tag.slug`. 주석 "T-307에서 연결"은 유지.
4. **content/posts/hello-world.mdx**: `tags: [blog, devlog, shader]`

## 검증
- `npm run lint`, `npx tsc --noEmit`, `npm run build` 통과
- 빌드 결과 HTML(홈·`/blog`·글 상세)에 `#블로그`·`#개발 일지`·`#셰이더`가 들어 있음
- 임시로 `tags.json` 키를 `Shader`로 바꿔 빌드 실패 메시지 확인 후 되돌림, 파일을 잠시 빼면 slug 그대로 표시되는지 확인 후 되돌림
- `getAllTags()`는 아직 사용처가 없으므로 T-307에서 화면 확인 (`out/blog/tags/shader` 생성은 T-308 완료 조건으로 넘김)

## 결정
- 2026-11-13: 완료 조건의 "`out/blog/tags/shader`가 생긴다"는 태그 페이지가 있어야 하므로 T-308 완료 조건으로 넘긴다. T-306은 대응표·로더·`getAllTags()`와 기존 카드·상세 칩의 한글 표시까지.
- 2026-11-13: 대응표 처음 값 blog→블로그, devlog→개발 일지, shader→셰이더. 샘플 글 hello-world에 `shader` 태그 추가. `tags.json`이 없으면 빈 대응표(빌드 실패 아님).
