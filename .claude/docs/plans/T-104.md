# T-104 기본 다크 모드와 네온 효과 유틸리티

> 승인일: 2026-11-08 · 로드맵: [ROADMAP](../ROADMAP.md)

## Context
- T-104~T-107을 한 계획으로 승인받아 진행 (레이아웃 파일이 겹침). T-103에서 넘긴 라이트 포커스 링 대비도 여기서 처리.

## 변경
- `app/layout.tsx`: `ThemeProvider defaultTheme="system"` → `"dark"` (시스템 옵션은 유지). 선택 값 저장·복원은 next-themes가 localStorage로 처리
- `app/globals.css`에 `@utility` 추가
  - `neon-glow` / `neon-glow-magenta`: 네온 테두리 + 바깥 글로우
  - `neon-text` / `neon-text-magenta`: 글자 글로우
  - `neon-hover`: 마우스를 올리거나 키보드 포커스 시 시안 테두리·글로우 (`prefers-reduced-motion`이면 전환 효과 없음)
- 라이트 포커스 링: shadcn 컴포넌트의 `ring-ring/50`(50%) 때문에, 라이트 `--ring`만 `--primary`와 분리해 더 어두운 청록으로. 50% 합성 시 흰 배경 대비 3:1 이상 (`components/ui`는 수정하지 않음)

## 결과 (2026-11-08)
- 라이트 `--ring`: `oklch(0.28 0.048 215)` (#022f38). `--primary`(`oklch(0.42 0.074 215)`)와 분리
  - 50% 합성 시 흰 배경 대비 **3.08:1** (기준 3:1 통과). 후보: L 0.36 → 2.74, 0.30 → 2.99, 0.28 → 3.08
  - 다크 `--ring`은 그대로 (50% 합성 3.85:1)
- 브라우저 확인: 저장값 없는 첫 방문 다크, 라이트로 바꾼 뒤 새로고침해도 라이트 유지(localStorage `theme=light`)
- 유틸리티 `neon-glow`, `neon-glow-magenta`, `neon-text`, `neon-text-magenta`, `neon-hover`가 빌드 CSS에 생성됨

## 수정 (2026-11-08)
- 리뷰 지적: `neon-hover`는 일반 유틸리티로 정렬돼 버튼의 `dark:border-input`, `transition-all`에 덮였음 → hover/focus 테두리 색과 동작 줄이기 `transition: none`에 `!important`. 모바일 메뉴에 `aria-current="page"` 추가
- 브라우저 확인: 다크 hover 테두리 = 네온 시안, 동작 줄이기 시 전환 0초, 키보드 포커스 링 유지
- **사용 시 주의 (재리뷰 메모):**
  - `neon-hover`의 테두리 `!important`는 hover·포커스 때 오류 표시(`aria-invalid:border-destructive`)나 다른 `hover:border-*`까지 덮음 → 폼 컨트롤·오류 상태가 있는 요소에는 쓰지 않음 (필요해지면 `:not([aria-invalid="true"])` 조건 추가)
  - 동작 줄이기의 `transition: none !important`는 그 요소의 모든 전환(배경색, 열림/닫힘)을 끔 — 동작 줄이기 취지에 맞는 의도된 동작

## 검증
- 첫 방문(저장값 없음) 다크, 라이트로 바꾸고 새로고침해도 유지
- 라이트 포커스 링 50% ≥ 3:1 (아래 결과에 기록)
