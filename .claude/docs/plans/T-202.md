# T-202 기술 브랜드 아이콘 라이브러리 확정 (스파이크)

> 승인일: 2026-11-09 · 로드맵: [ROADMAP](../ROADMAP.md)

## 결정
- 라이브러리: **simple-icons** (`dependencies`)
- 색: 브랜드 색(`hex`)은 쓰지 않고 **글자색 단색**(`fill="currentColor"`)으로 그려 테마를 따라감
- 아이콘이 없는 기술: **텍스트 이니셜** (예: `C#`)을 아이콘과 같은 크기로 표시
- 함께 나온 요청: 사이트의 네온(시안+마젠타 글로우)을 **블랙 + 차분한 시안 1색**으로 바꾸기 → ROADMAP에 "테마 색 리뉴얼" 작업으로 추가 (따로 계획·승인)

## 라이선스와 상표
- **패키지는 CC0-1.0이지만 아이콘마다 라이선스가 따로 있습니다** (패키지의 `DISCLAIMER.md`: 모든 아이콘이 CC0라는 뜻은 아님). 아이콘 객체의 `license`·`guidelines` 필드로 확인합니다.

  | 아이콘 | `license` | 해야 할 일 |
  |------|------|------|
  | Godot Engine | **CC-BY-4.0** | **출처 표기 필요** (예: 소개 페이지나 푸터 크레딧에 "Godot logo by the Godot Engine contributors, CC BY 4.0") |
  | Unity·Unreal Engine·Blender·GitHub·YouTube | 없음 (`guidelines`에 브랜드 지침 URL) | 각 회사 브랜드 지침을 따름 |
  | C++ | 없음 | — |

- 로고는 각 회사의 상표이므로 해당 기술을 썼다는 표시로만 쓰고, 로고를 변형하거나 광고처럼 쓰지 않습니다. 단색(`currentColor`) 표시는 위 지침과 충돌하지 않습니다.
- C#·Visual Studio·VS Code·LinkedIn·Photoshop은 simple-icons에 없습니다 (상표 문제로 빠진 것으로 알려져 있으나 패키지 안에서 근거는 확인하지 못함). 새 버전에서 아이콘이 빠질 수 있으므로 T-204의 대응표는 없는 아이콘을 이니셜로 처리해야 합니다.
- T-204에서 새 아이콘을 추가할 때마다 `license`를 확인하고, CC-BY 계열이면 출처 표기를 함께 넣습니다.
- react-icons(MIT)는 `si` 세트의 데이터를 simple-icons에서 가져오고 패키지가 84MB라 고르지 않았습니다.
- Lucide(1.70)에는 GitHub·YouTube 같은 브랜드 아이콘이 없습니다 (일반 아이콘만).

## 사용 방법 (T-204에서 구현)
- `import { siUnity } from "simple-icons"`처럼 쓴 아이콘만 번들에 들어갑니다 (`sideEffects: false` ESM).
- 아이콘 객체의 `path`를 서버 컴포넌트에서 `<svg viewBox="0 0 24 24" fill="currentColor">`로 그립니다. `"use client"`가 필요 없습니다.
- 접근성: `TechBadge`처럼 옆에 기술 이름 글자가 함께 있으면 `aria-hidden="true"`로 숨깁니다 (이름을 두 번 읽지 않게). 아이콘만 보일 때만 `role="img" aria-label={title}`을 씁니다.
- `TechBadge`가 기술 이름 → 아이콘 대응표를 갖고, 대응표에 없으면 이니셜을 보여 줍니다.
