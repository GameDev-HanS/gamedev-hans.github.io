# T-310 basePath 대응 이미지 경로 처리

> 승인일: 2026-11-14 · 로드맵: [ROADMAP](../ROADMAP.md)

## Context
`next.config.ts`의 `basePath`는 `PAGES_BASE_PATH`에서 오지만, Next 16 문서(`basePath.md` "Images")대로 `next/image` src·일반 `<img>`·메타데이터 절대 주소에는 basePath가 자동으로 붙지 않는다. 지금은 값이 비어 문제없지만, 프로젝트 사이트(user.github.io/repo)로 배포하면 썸네일·본문 이미지·프로필 사진·게임 표지가 깨지고 canonical·og·sitemap 주소가 틀어진다. 배경 음악(`lib/music.ts`)만 직접 붙이고 있다. 공용 함수 하나로 모두 처리한다.

## 변경
1. **새 파일 `lib/base-path.ts`** (서버 컴포넌트·빌드 시 전용, 클라이언트 번들에서는 env가 비어 있음을 주석으로 명시)
   - `basePath = process.env.PAGES_BASE_PATH ?? ""`
   - `withBasePath(path)`: `/`로 시작하고 `//`가 아니면 앞에 basePath, 그 외(외부 URL·data: 등)는 그대로
   - `siteUrl = ${siteConfig.url}${basePath}` — 메타데이터·sitemap·robots용 전체 주소
2. **이미지 src에 `withBasePath`**
   - `components/shared/post-card.tsx`, `components/sections/post-header.tsx` (글 썸네일)
   - `components/shared/game-card.tsx` (게임 표지)
   - `components/sections/profile-intro.tsx` (프로필 사진)
   - `mdx-components.tsx`의 `img` (본문 이미지 — `src`가 문자열일 때만)
3. **`lib/music.ts`**: 직접 붙이던 코드를 `withBasePath(/audio/<file>)`로 교체
4. **메타데이터·주소**
   - `app/layout.tsx`: `metadataBase: new URL(siteUrl)`, `openGraph.url: siteUrl`. Next의 `resolveUrl`이 metadataBase의 pathname을 이어 붙이므로(`resolve-url.js` 확인) 각 페이지의 canonical·og:url·og:image는 자동으로 basePath 포함 → `lib/metadata.ts`, `app/blog/[slug]/page.tsx`는 수정 불필요
   - `app/sitemap.ts`, `app/robots.ts`: `siteConfig.url` → `siteUrl`
   - `config/site.ts`는 그대로 (클라이언트 컴포넌트도 import하므로 env를 넣지 않음)

## 검증
1. `npm run lint`, `npx tsc --noEmit`
2. `PAGES_BASE_PATH=/test-base`로 `npm run build` 후 `out/`에서 이미지 src, canonical·og, sitemap·robots 확인
3. env 없이 다시 빌드 → 기존과 같은 경로
4. 화면 변화 없음 → 커밋은 `/commit`

## 결정
- 2026-11-14: `lib/base-path.ts`의 `basePath`·`withBasePath`·`siteUrl`은 서버 컴포넌트·lib 전용 (`PAGES_BASE_PATH`는 클라이언트 번들에서 비어 있음). 클라이언트 컴포넌트에는 서버에서 계산한 경로를 props로 넘긴다 (프로필 사진 `AvatarImage`가 이 방식).
- 2026-11-14: `config/site.ts`의 `url`은 basePath 없는 도메인으로 유지하고, 메타데이터·sitemap·robots는 `siteUrl`을 쓴다. `metadataBase`에 basePath가 들어가 canonical·og:url·og:image는 따로 고칠 필요 없음.
- 2026-11-14 검증: `PAGES_BASE_PATH=/test-base` 빌드에서 글 카드·상세 대표 이미지·MDX 본문 이미지·프로필 사진·og:image·canonical·og:url·sitemap·robots 모두 `/test-base` 포함 확인 (글 이미지는 임시 썸네일을 넣어 확인 후 되돌림). 게임 표지는 현재 데이터에 `cover`가 없어 빌드로는 확인하지 못했고 같은 `withBasePath`를 씀. env 없이 빌드하면 기존과 같은 주소.
- 2026-11-14 리뷰(문제 없음, 사소 메모): ① `PAGES_BASE_PATH`는 앞 슬래시 필수·끝 슬래시 금지(`/repo`) — next.config `basePath`와 같은 제약, T-311 작성 가이드에 한 줄 적기. ② 프로젝트 `thumbnail`은 지금 화면에 쓰이지 않음 → 프로젝트 카드(T-205·T-215)에서 이미지를 그릴 때 `withBasePath` 적용. ③ 글 og:image는 상대 경로 + metadataBase로 basePath가 붙음(코드 변경 없음).
