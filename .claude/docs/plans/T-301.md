# T-301 코드 블록 하이라이트와 전용 패널

> 승인일: 2026-11-13 · 로드맵: [ROADMAP](../ROADMAP.md)

## Context
블로그 글(MDX)의 코드 블록이 지금은 prose 기본 `pre` 스타일로만 보이고 하이라이트가 없습니다. 게임 개발 글(C#·C++·HLSL)을 쓰려면 빌드 시 하이라이트와 본문과 구분되는 전용 패널이 필요합니다. ROADMAP T-301 완료 조건 ①~⑥이 기준입니다.

## 결정 (사용자 답변)
- 색 테마: shiki `github-light` / `github-dark` (글자 색만, 패널 배경은 사이트 테마 변수)
- 언어 표시 이름: 로드맵 가정 그대로 — C#, C++, HLSL, GLSL, TypeScript, JavaScript, JSON, Shell (별칭 cs·c#·c++·ts·js·sh·bash 포함). 표에 없으면 적은 이름 그대로

## 변경
1. **package.json**: `rehype-pretty-code`, `shiki` 설치. 설치 후 shiki `bundledLanguages`에서 `csharp`·`cpp`·`hlsl`·`glsl`·`typescript` 지원 확인해 `## 결정`에 기록
2. **next.config.ts**: `rehypePlugins`에 문자열로 추가 (Turbopack은 직렬화 가능한 옵션만)
   `["rehype-pretty-code", { theme: { light: "github-light", dark: "github-dark" }, keepBackground: false, bypassInlineCode: true }]`
   - `defaultLang`은 지정하지 않음 → 언어 없는 블록은 하이라이트 없이 그대로 (조건 ③)
   - 인라인 코드는 건드리지 않음 (기존 prose-code 스타일 유지)
3. **components/shared/code-block.tsx** (새 파일, 서버 컴포넌트, JS 없음): `not-prose` 래퍼(`rounded-lg border bg-card`) + 언어가 있으면 상단 바에 표시 이름 + `overflow-x-auto` `pre`. `LANGUAGE_LABELS` 변환표와 `getLanguageLabel(lang)` (없으면 원래 이름)
4. **mdx-components.tsx**: `pre`를 `CodeBlock`으로 연결 (`data-language`로 언어 받음)
5. **app/globals.css**: `--shiki-light`/`--shiki-dark` 두 테마 색 전환과 figure 여백
6. **content/posts/hello-world.mdx**: 확인용 코드 블록 추가 — C#, HLSL, 언어 없는 블록, 긴 줄 하나

## 주의
- 지원하지 않는 언어 이름을 적었을 때 빌드가 멈추는지 확인하고, 멈추면 처리 방법을 `## 결정`에 기록
- `"use client"` 추가 없음, 복사 버튼·줄 번호·파일 이름 없음 (조건 ⑤)

## 확인
- `npm run lint`, `npx tsc --noEmit`, `npm run build` (조건 ⑥)
- `out/` HTML에 `--shiki-light`/`--shiki-dark` 스타일과 `data-language` 확인
- 브라우저: `/blog/hello-world`에서 다크·라이트 전환 시 코드 색 변화, 상단 바 "C#"·"HLSL", 언어 없는 블록은 상단 바 없음, 375px에서 긴 줄이 패널 안에서만 가로 스크롤
