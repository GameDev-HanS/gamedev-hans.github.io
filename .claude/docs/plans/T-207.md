# T-207 푸터 외부 링크를 profile.json links로 옮기기

> 승인일: 2026-11-13 · 로드맵: [ROADMAP](../ROADMAP.md)

## Context
푸터 외부 링크가 아직 `config/site.ts`의 임시 값(`siteConfig.links`, GitHub 하나)을 씁니다. 소개 데이터는 `content/profile.json`의 `links`(GitHub·solved.ac)로 옮겨 두었으므로, 푸터도 그 값을 쓰게 하고 임시 값을 지웁니다. (2026-11-13 소개 페이지가 없어져 작업 범위가 이것으로 축소됨)

## 결정 (사용자 답변)
- 표시: 지금처럼 **작은 글자 링크만** (아이콘 없음). solved.ac처럼 `icon`이 없는 링크도 같은 모양

## 변경
1. **`app/layout.tsx`**: `getProfile()`(`lib/content.ts`, server-only)로 `links`를 읽어 `<SiteFooter links={profile.links} music={music} />`로 넘김. 레이아웃은 서버 컴포넌트라 그대로 가능
2. **`components/layout/site-footer.tsx`**: `siteConfig.links` 대신 `links: Profile["links"]` prop 사용 (`import type`만), `label`·`url`로 렌더. 새 탭 `target="_blank" rel="noopener noreferrer"` 유지, `key`는 url. 저작권 줄의 `siteConfig.name`은 그대로
3. **`config/site.ts`**: `links` 항목과 주석 삭제 (다른 사용처 없음 — Grep 확인)

URL은 로더가 http/https만 허용하므로(mailto·tel 차단) 푸터에서 추가 검사는 하지 않음.

## 확인
- `npm run lint`, `npx tsc --noEmit`, `npm run build`
- 브라우저: 푸터에 GitHub·solved.ac 두 링크, 둘 다 새 탭 속성, 375px에서 줄바꿈·가로 스크롤 없음
- `siteConfig.links` 검색 결과 0건

## 결정
- 2026-11-13 (리뷰 반영): `getProfile()`에 `links`의 url 중복 검사 추가 (같은 주소가 두 번이면 빌드 실패). `readJson` 파일 없음 메시지를 '홈 소개 섹션·푸터에 필요한 데이터'로 변경 — 이제 `profile.json`이 없거나 틀리면 레이아웃(푸터) 때문에 모든 페이지 빌드가 실패함.
- 2026-11-13 (다음 문서 갱신 때 정리): T-207 이후 낡은 문구 — ROADMAP 3·28·101행과 6장 미결 '실제 값' 항목, PRD 276·439행의 '푸터가 아직 임시 값 사용 / links는 데이터로만 있음'을 현재 기준(푸터가 profile.json links 사용)으로 고치기.
