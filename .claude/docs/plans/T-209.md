# T-209 게임 기록 스키마·로더 (기존 2026.json 검증)

> 승인일: 2026-11-09 · 로드맵: [ROADMAP](../ROADMAP.md)

## Context
- 게임 페이지(T-210~T-213)가 읽을 데이터 로더를 만듭니다. 데이터는 사용자가 준 실제 기록 `content/games/2026.json`(10개)이 이미 있고, 이 파일이 **수정 없이** 통과해야 합니다.
- 사용자 결정: `status`는 선택이며 **cleared·playing·dropped·wishlist 네 가지 허용**(지금은 두 가지만 씀), 표지는 **`cover`(선택) + `coverCredit`(cover가 있으면 필수)**.
- PRD 데이터 모델은 예전 형식(`clearedAt`, `status` 필수)이라 product-manager로 함께 고칩니다.
- 재사용: `lib/posts.ts`의 `server-only`, `cache()`, 한국어 `required()` 메시지, `SLUG` 정규식, 날짜 검증, 파일 이름이 들어간 오류 메시지, public 파일 존재 확인. 공통 부분은 `lib/schema.ts`로 옮겨 두 로더가 함께 씁니다.

## lib/games.ts
- 필수: `slug`, `title`, `platforms`(1개 이상)
- 선택: `status`(cleared/playing/dropped/wishlist), `rating`(1~5 정수), `comment`, `playtime`(0 이상), `startedAt`·`endedAt`(YYYY-MM-DD, 실제 날짜), `cover`(`/images/games/<연도>/`, 실제 파일), `coverCredit`
- `.strict()`: 모르는 필드(예: `clearedAt`)는 실패
- 교차 검사: `endedAt` < `startedAt` 실패, `cover`만 있고 `coverCredit` 없으면 실패, 같은 파일 slug 중복 실패
- 파일 이름 `^\d{4}\.json$`, 배열 여부, JSON 문법 오류도 파일 이름과 함께 실패
- 공개 함수: `getGameYears()`(최신순), `getGamesByYear(year)`(파일 순서, 없으면 null), 타입 `Game`·`GameStatus`. 폴더를 인자로 받는 `readGamesDir(dir)`로 스크래치 폴더 검증 가능
- 아직 페이지에서 쓰지 않으므로 빌드 자동 검증은 T-212·T-213부터

## 검증
1. lint·tsc·build 통과
2. 스크립트로 `getGameYears()` → `[2026]`, 2026년 10개, 2025년 null
3. 스크래치 복사본 폴더에서 잘못된 값마다 실패 메시지(파일 이름 포함) 확인 — 실제 2026.json은 건드리지 않음
4. 리뷰 → ROADMAP 체크 → `/commit`
