# T-201 소개용 JSON 스키마와 로더

> 승인일: 2026-11-12 · 로드맵: [ROADMAP](../ROADMAP.md)

## Context
단계 2 소개 페이지(T-203~T-208)와 홈 히어로가 쓸 데이터(`profile`·`skills`·`projects`·`timeline`)를 JSON 파일로 두고, 빌드 시 zod로 검증하는 로더를 만든다. 잘못된 데이터(이메일·전화 링크, 없는 기술 이름, 아이콘 오타)는 파일 이름이 들어간 메시지로 빌드를 실패시켜 배포되지 않게 한다. 화면 변경은 없다 (T-203부터 사용).

## 사용자 결정 (2026-11-12)
- 예시 데이터: 자리표시 값. 이름 `HanS`, GitHub `https://github.com/GameDev-HanS`만 실제 값, 나머지는 "(예시)"가 붙은 임시 값
- `icon`(simple-icons slug)을 적었는데 simple-icons에 없으면 **빌드 실패**, 비우면 이니셜 (T-204)
- 프로젝트 `thumbnail`·`link`는 **선택** (없으면 자리표시·링크 버튼 숨김 — T-205)

## 구현 — `lib/content.ts` (새 파일, `import "server-only"`)
`lib/games.ts` 패턴을 따름: BOM 제거 후 `JSON.parse`, 실패 시 `content/<파일>: JSON 형식이 올바르지 않습니다`, 스키마는 `.strict()`, 오류는 `lib/schema.ts`의 `formatIssues`·`required`·`SLUG`로 한국어 메시지. 각 로더는 `react`의 `cache`로 감쌈. 파일이 없으면 실패(필수 콘텐츠).

| 파일 | 스키마 |
|------|------|
| `profile.json` (객체) | `name`, `tagline` 필수 · `photo` 선택(`/images/profile/…`, 파일 존재 검사) · `interests`·`studying` 문자열 배열 · `links` `{label, url, icon?}` 배열 |
| `skills.json` (배열) | `name`, `category`(engine/language/tool) · `icon` 선택. `name` 중복 실패 |
| `projects.json` (배열) | `slug`(SLUG), `title`, `summary`, `stack`(1개 이상) · `thumbnail` 선택(`/images/projects/…`, 파일 존재) · `link` 선택. `slug` 중복 실패 |
| `timeline.json` (배열) | `period`, `title`, `organization`, `type`(work/education) · `description` 선택. 파일 순서 = 표시 순서 |

공통 검증:
- **URL**(`links[].url`, `projects[].link`): `z.url({ protocol: /^https?$/ })` — `mailto:`·`tel:`·`javascript:` 등은 "이메일·전화번호 링크는 넣지 않습니다 (http/https만)" 메시지로 실패 (`lib/music.ts`의 `sourceUrl`과 같은 방식)
- **아이콘**(`skills[].icon`, `links[].icon`): `import * as icons from "simple-icons"`의 `slug` 집합으로 확인, 없으면 실패. 서버 전용 로더라 클라이언트 번들에 들어가지 않음
- **관계**: `projects[].stack`의 이름이 `skills.json`의 `name`에 없으면 실패 (`getProjects()`가 `getSkills()`를 불러 확인)
- 경로 필드는 `..` 금지 정규식 (games의 `cover`와 같은 방식)

공개 함수: `getProfile()`, `getSkills()`, `getProjects()`, `getTimeline()` + 타입 `Profile`, `Skill`, `SkillCategory`, `Project`, `TimelineItem`.

## 예시 데이터 (`content/`)
- `profile.json`: name `HanS`, tagline/interests/studying "(예시)…", links GitHub 1개, photo 없음
- `skills.json`: 세 분류 각 1개 이상 (CC-BY인 Godot은 출처 표기가 필요해 예시에서 제외), C#은 아이콘 없음
- `projects.json`: 예시 2개 (썸네일 없음, 하나만 링크)
- `timeline.json`: work 1개, education 1개

`config/site.ts`의 `links`는 T-207에서 옮기므로 이번엔 그대로 둠.

## 검증
1. `npm run lint`, `npx tsc --noEmit`, `npm run build` 통과. 확인할 때만 `app/about/page.tsx`에서 네 로더를 임시로 호출
2. 실패 확인(임시로 넣고 되돌림): `mailto:`·`tel:` 링크, stack에 없는 기술, icon 오타, 잘못된 category, 모르는 필드, photo 파일 없음
3. 임시 호출은 커밋 전에 모두 제거

## 결정
- 2026-11-12: 예시 skills에서 Git(`git`)은 simple-icons 라이선스가 CC-BY-3.0이라 빼고 GitHub로 대체 (예시 아이콘은 모두 `license` 없음: github·unity·unrealengine·cplusplus·blender). 아이콘을 추가할 때는 `license` 확인 (T-202).
- 2026-11-12: 검증은 about 페이지 임시 호출 대신, 저장소 밖 임시 스크립트로 `tsx --conditions=react-server`에서 로더를 직접 실행해 확인함 (저장소 코드를 건드리지 않음). 실패 사례 10개(mailto·tel 링크, photo 파일 없음, stack에 없는 기술, 아이콘 오타, 잘못된 category·type, 기술 이름 중복, 모르는 필드, slug 형식) 모두 파일 이름이 들어간 메시지로 실패.
- 2026-11-12 (리뷰 반영): 프로젝트 `stack` 안 기술 이름 중복이면 빌드 실패 추가, BOM 제거 정규식을 `﻿` 이스케이프로. `SKILL_CATEGORIES`·`TIMELINE_TYPES`는 server-only 파일에 그대로 둠 (클라이언트에서 값이 필요해지면 별도 파일로 분리 — 타입 import는 안전).
- 2026-11-12: ROADMAP의 단계 1 완료 정리(T-125 커밋 뒤 갱신 에이전트 반영분)는 T-201 커밋에 함께 포함 (사용자 결정).
- 2026-11-12: 로더 오류 메시지는 "n번째 <기술/프로젝트/경력·학력> 항목이 올바르지 않습니다 — 필드: 이유" 형식. 모르는 필드는 zod 기본 메시지(`Unrecognized key`)로 나옴 (games 로더와 같음).
