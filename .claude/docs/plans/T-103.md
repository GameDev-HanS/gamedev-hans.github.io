# T-103 시안·마젠타 네온 테마 변수 정의

> 승인일: 2026-11-08 · 로드맵: [ROADMAP](../ROADMAP.md)

## Context
- T-102와 함께 진행. 포인트 색은 시안(주) + 마젠타(보조), 라이트 모드는 대비를 위해 밝기·채도를 낮춘 값.

## 변경 (app/globals.css)
- 새 CSS 변수 (`:root` = 라이트, `.dark` = 다크 각각 정의)
  - `--neon-cyan`, `--neon-magenta`: 텍스트·테두리용 포인트 색
  - `--neon-cyan-glow`, `--neon-magenta-glow`: 글로우(box-shadow·text-shadow)용 반투명 색
- `@theme inline`에 `--color-neon-cyan`, `--color-neon-magenta` 등록 → `text-neon-cyan`, `border-neon-magenta` 같은 Tailwind 클래스로 사용
- 기본 테마 색과 연결: `--primary`, `--ring`을 시안으로 바꿔 버튼·포커스 링이 테마를 따르게 함 (`--primary-foreground`는 시안 위에서 읽히는 색으로 맞춤)
- 다크 기본값·글로우 유틸리티(`@utility`)는 T-104에서

## 대비 측정 (완료 조건)
- oklch → sRGB 변환 후 WCAG 대비를 계산하는 Node 스크립트로 측정. 결과는 아래 "결과"에 기록.

## 수정 (2026-11-08)

코드 리뷰에서 반투명 상태가 측정에서 빠진 점을 지적받음. 버튼 hover는 `bg-primary/80`이라 흰 배경과 섞여 라이트 모드에서 흰 글자 대비가 3.49:1로 미달.
- 브라우저처럼 sRGB에서 배경과 합성해 다시 계산하고, 라이트 시안을 `oklch(0.52 0.088 215)` → `oklch(0.42 0.074 215)`(#015766)로 어둡게 조정 (`--primary`, `--ring`, `--neon-cyan`, glow 모두)

| 모드 | 조합 | 대비 | 결과 |
|------|------|------|------|
| 라이트 | 시안 글자 / 배경 | 8.23:1 | 통과 |
| 라이트 | 버튼 글자 / 시안 버튼 | 7.88:1 | 통과 |
| 라이트 | 버튼 글자 / hover(시안 80%) | 4.80:1 | 통과 |
| 다크 | 버튼 글자 / hover(시안 80%) | 8.53:1 | 통과 |
| 라이트 | 포커스 링(시안 50%) / 배경 | 2.51:1 | 기준(3:1) 미달 — 아래 참고 |
| 다크 | 포커스 링(시안 50%) / 배경 | 3.85:1 | 통과 |

- 라이트 포커스 링: shadcn 컴포넌트가 `ring-ring/50`(50% 투명)을 쓰기 때문에 색을 어둡게 해도 3:1에 닿지 않음 (L 0.40에서도 2.58). 예전 회색 링보다는 진해져 나빠진 것은 아님. 컴포넌트의 링 투명도를 바꿔야 해결되므로 T-104(네온 효과·호버/포커스 스타일)에서 다룸.
- 배지 링크 hover(`[a]:hover:bg-primary/80`)도 버튼과 같은 계산이라 함께 해결됨.

2. 포인트 색 vs 배경, `--primary-foreground` vs `--primary` 대비가 모두 4.5:1 이상
