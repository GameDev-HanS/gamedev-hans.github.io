# 게임 개발자 개인 블로그 MVP PRD

> 작성일: 2026-11-08 · 수정일: 2026-11-09 (테마를 블랙 + 시안 1색으로 변경) · 지침: .claude/docs/prd-guide.md

## 🎯 핵심 정보

**목적**: 게임 개발자가 자신을 소개하고, 공부하고 개발한 내용을 글·사진·영상 포스트로, 좋아하고 플레이 중인 게임을 연도별 기록으로 남기고 보여 줄 개인 사이트를 만든다.
**사용자**: 운영자의 기술 스택·프로젝트·개발 기록을 보러 오는 채용 담당자, 동료 게임 개발자, 게임 개발을 공부하는 사람

## 🚶 사용자 여정

```
[홈 페이지]
    ↓ 첫 화면에서 한 줄 소개와 최근 글 확인
    ├─ "소개 보기" 클릭 / 헤더 "소개" ──→ [소개 페이지]
    ├─ 최근 글 카드 클릭 / 헤더 "블로그" ──→ [블로그 목록 페이지] 또는 [글 상세 페이지]
    └─ 헤더 "게임" ──→ [연도 선택 페이지]

[연도 선택 페이지]
    ↓ 연도 카드 목록(최신 연도가 앞, 처음엔 2026 하나)과 연도별 상태별 게임 수 확인
    └─ 연도 카드 클릭 → [플레이 게임 페이지] (선택한 연도)

[플레이 게임 페이지]
    ↓ 선택한 연도의 게임 카드를 상태별로 확인
    ├─ 연도 전환 탭에서 다른 연도 클릭 → [플레이 게임 페이지] (선택한 연도)
    ├─ 헤더 "게임" 클릭 → [연도 선택 페이지]
    └─ 없는 연도로 접근 → [404 페이지]

[소개 페이지]
    ↓ 프로필·기술 스택·프로젝트·경력 타임라인 확인
    ├─ 외부 링크(GitHub, YouTube 등) 클릭 → 새 탭에서 외부 사이트
    └─ "블로그 보기" 클릭 → [블로그 목록 페이지]

[블로그 목록 페이지]
    ↓ 최신순 글 카드 훑어보기
    ├─ 글 카드 클릭 → [글 상세 페이지]
    └─ 태그 칩 클릭 → [태그별 글 목록 페이지]

[태그별 글 목록 페이지]
    ├─ 다른 태그 칩 클릭 → [태그별 글 목록 페이지] (다른 태그)
    ├─ "전체 글" 클릭 → [블로그 목록 페이지]
    └─ 글 카드 클릭 → [글 상세 페이지]

[글 상세 페이지]
    ↓ 본문·사진·영상 감상
    ├─ 본문의 태그 클릭 → [태그별 글 목록 페이지]
    ├─ 이전/다음 글 클릭 → [글 상세 페이지] (다른 글)
    └─ "목록으로" 클릭 → [블로그 목록 페이지]

[없는 주소로 접근] → [404 페이지] → "홈으로" 클릭 → [홈 페이지]

[모든 페이지 공통 — 헤더 배경 음악 버튼 (음원 파일이 있을 때만 보임)]
    ↓ 방문할 때마다 항상 꺼짐 상태에서 시작
    ├─ 버튼 클릭 (꺼짐 → 켜짐) → 배경 음악 반복 재생
    │     └─ 헤더·카드·탭 등 사이트 안 링크로 다른 페이지 이동 → 음악이 끊기지 않고 이어서 재생
    ├─ 버튼 다시 클릭 (켜짐 → 꺼짐) → 음악 정지
    └─ 다음 방문·새로고침·새 탭·주소 직접 입력 → 다시 꺼짐에서 시작 (켜짐을 기억하거나 자동 재생을 시도하지 않음)

[모든 페이지 공통 — UI 애니메이션 (F016)]
    ↓ 사이트에 처음 들어옴 (첫 접속·새로고침)
    ├─ 헤더 메뉴 항목이 왼쪽부터 차례로 나타남 (투명도·위치 전환) → 홈이면 히어로·최근 글도 차례로 등장
    ├─ 아래로 스크롤 → 카드·섹션이 화면에 들어올 때 아래에서 살짝 올라오며 나타남 (한 번만)
    ├─ 헤더·카드·탭 등으로 페이지 이동 → 이전 페이지가 흐려지고 새 페이지가 부드럽게 나타남 (헤더·푸터는 그대로)
    ├─ 카드·버튼·링크에 마우스 올림 → 카드가 살짝 떠오르고 기울며 테두리가 포인트 색(시안)으로 바뀜, 링크·메뉴 색 전환
    └─ 운영체제 "동작 줄이기" 설정 → 이동·기울기 없이 짧은 투명도 전환만 (또는 즉시 표시)
```

- 자동 리디렉션은 없다 (로그인·권한 분기 없음).
- 테마는 첫 방문 시 다크 모드, 방문자가 바꾸면 브라우저에 저장된 값을 따른다.
- 배경 음악은 방문할 때마다 꺼짐에서 시작하고, 켜고 끈 선택은 저장하지 않는다. 같은 방문 안에서 사이트 링크로 이동할 때만 이어서 재생한다 (F015).
- 애니메이션은 방문자의 운영체제 "동작 줄이기" 설정을 따른다 (F016).

## ⚡ 기능 명세

### 1. MVP 핵심 기능

| ID | 기능명 | 설명 | MVP 필수 이유 | 관련 페이지 |
|----|--------|------|-------------|------------|
| **F001** | 자기소개 프로필 | 사진(선택), 이름, 한 줄 소개, 관심 분야, "지금 공부 중인 것" 목록 표시 | 사이트의 1순위 목적인 운영자 소개 | 소개 페이지 |
| **F002** | 기술 스택 배지 | 엔진·언어·도구를 분류별로 아이콘이 붙은 배지로 표시. 아이콘은 브랜드 색 대신 글자색 단색으로 그려 테마를 따라가고, 아이콘이 없는 기술(C# 등)은 텍스트 이니셜로 표시 | 게임 개발자의 역량을 한눈에 전달 | 소개 페이지 |
| **F003** | 프로젝트 카드·경력 타임라인 | 대표 프로젝트 카드(썸네일, 제목, 요약, 사용 기술, 외부 링크)와 경력·학력 세로 타임라인 | 실제 작업물과 이력 증명 | 소개 페이지 |
| **F004** | 외부 링크 목록 | GitHub, YouTube 등 외부 채널 링크 버튼(새 탭). 이메일·전화번호는 넣지 않음 | 방문자가 다른 채널로 이어지게 함 | 소개 페이지 |
| **F005** | 홈 하이라이트 | 포인트 색(시안)으로 강조한 히어로(이름·한 줄 소개·"소개 보기" 버튼)와 최근 글 3개 카드 | 첫 화면에서 정체성과 최신 활동 전달 | 홈 페이지 |
| **F006** | 글 목록 | 모든 글을 최신순 카드(썸네일, 제목, 요약, 작성일, 태그)로 표시 | 블로그 탐색의 시작점 | 블로그 목록 페이지 |
| **F007** | 글 본문 보기 | MDX 본문(제목, 작성일, 태그, 사진, 코드 블록)과 이전/다음 글 링크. 코드 블록은 본문과 구분되는 전용 배경 패널에 문법 하이라이트로 보여 주고, 패널 상단에 언어 이름(C#, C++, HLSL 등)을 표시 (복사 버튼·줄 번호·파일 이름은 없음) | 개발 기록 전달의 핵심 (코드가 본문과 섞이지 않아야 읽기 쉬움) | 글 상세 페이지 |
| **F008** | 영상 재생 | 글 안에 넣은 Supabase Storage 공개 URL 영상을 사이트의 비디오 플레이어(재생·일시정지·전체 화면 등 브라우저 기본 컨트롤)로 재생 | 게임 플레이·개발 결과는 영상이 가장 잘 보여 줌 | 글 상세 페이지 |
| **F009** | 태그별 글 걸러 보기 | 태그 하나를 고르면 그 태그가 붙은 글만 최신순으로 표시, 전체 태그 칩 목록 제공 | 주제별로 글을 찾는 유일한 수단 | 태그별 글 목록 페이지 |
| **F013** | 플레이 게임 카드 | 한 연도의 게임을 상태별(플레이 중 → 클리어 → 중단 → 하고 싶은 게임) 묶음 카드로 표시. 카드에 표지 이미지, 제목, 플랫폼 배지(PC/PS5/Switch 등), 상태 배지, 평점, 한 줄 소감, 플레이 시간, 시작일, 클리어일을 보여 줌 (값이 없는 항목은 숨김) | 운영자가 어떤 게임을 좋아하고 플레이 중인지 보여 주는 새 페이지의 본체 | 플레이 게임 페이지 |
| **F014** | 연도별 게임 기록 전환 | 헤더 "게임"은 연도 선택 페이지(데이터가 있는 연도의 카드 목록, 최신 연도가 앞)를 보여 주고, 연도 카드를 고르면 그 연도의 플레이 게임 페이지로 이동. 연도마다 빌드 시 페이지를 하나씩 만들고(2026년부터), 연도 페이지 안의 연도 전환 탭으로 다른 연도를 오감. 없는 연도는 404. 새 연도는 데이터 파일만 추가하면 연도 카드·탭·페이지가 늘어남 | 해마다 기록이 쌓여도 지난 기록을 유지하며 볼 수 있어야 함 | 연도 선택 페이지, 플레이 게임 페이지 |

### 2. MVP 필수 지원 기능

| ID | 기능명 | 설명 | MVP 필수 이유 | 관련 페이지 |
|----|--------|------|-------------|------------|
| **F010** | 공통 레이아웃·내비게이션 | 헤더 메뉴, 푸터(외부 링크), 모바일 메뉴, 다크/라이트 전환(기본 다크), 404 처리 | 모든 페이지를 오가기 위한 최소 구조 | 모든 페이지 |
| **F011** | 콘텐츠 불러오기 | 저장소의 MDX 글, JSON 프로필 데이터, 연도별 게임 기록 JSON을 빌드 시 읽어 페이지·태그 목록·연도 목록을 만듦. 운영자는 파일을 커밋·푸시하면 반영 | 로그인·관리자 화면 없이 운영자만 작성 | 홈 페이지, 소개 페이지, 블로그 목록 페이지, 태그별 글 목록 페이지, 글 상세 페이지, 연도 선택 페이지, 플레이 게임 페이지 |
| **F012** | 게임 개발자 테마 | "블랙 + 차분한 시안 1색"의 모던한 테마(Vercel·Linear 느낌)를 다크/라이트 양쪽 테마 변수로 정의해 전 페이지에 적용. 다크(기본): 배경 약 #0A0A0B, 카드 약 #131316, 테두리 약 #26262B, 본문 글자 약 #EDEDEF, 보조 글자 약 #8B8B93, 포인트는 채도를 낮춘 시안 약 #5CC8D8 한 색. 라이트: 같은 원칙(무채색 + 진한 시안 1색). 두 모드 모두 명암비 WCAG AA 이상. 마젠타·글자 글로우는 쓰지 않고, 카드·버튼 호버 강조는 테두리가 포인트 색으로 바뀌고 아주 옅은 그림자가 생기는 정도. 게임 개발 콘셉트는 색이 아닌 문구(404의 "GAME OVER" 등)로 살림. 움직임(등장·전환·떠오름)은 F016이 담당하고 F012는 색·테두리·그림자 모양만 정의 | 사용자가 요구한 사이트 개성의 핵심 | 모든 페이지 |
| **F015** | 배경 음악 켜기/끄기 | 헤더의 게임 느낌 음악 버튼(켜짐·꺼짐 아이콘과 포인트 색 강조로 상태 표시)으로 저장소의 음원 한 곡을 반복 재생하거나 멈춤. 방문할 때마다 항상 꺼짐에서 시작하고 켜짐 상태를 기억하지 않음(자동 재생 시도 없음). 같은 방문 안에서 사이트 링크로 페이지를 옮길 때만 끊기지 않고 이어서 재생. 음원 파일이 없으면 버튼을 숨김. 푸터에 곡 출처·라이선스 문구 표시(음원이 없으면 문구도 숨김) | 사용자가 요청한 게임 같은 분위기 연출. 자동 재생이 막혀 있어 방문자가 직접 켜는 버튼이 필요 | 모든 페이지 (공통 레이아웃: 헤더·푸터) |
| **F016** | 모던 UI 애니메이션 | 사이트 전체에 깔끔하고 짧은 애니메이션 적용. ① 첫 진입 연출: 첫 접속·새로고침 때 헤더 메뉴 항목이 차례로(스태거) 나타나고, 홈 히어로·최근 글이 투명도·위치 전환으로 등장 ② 스크롤 등장: 카드·섹션이 화면에 들어올 때 아래에서 살짝 올라오며 투명도 0→1, 여러 카드는 차례로 (한 번만 재생) ③ 페이지 전환: 메뉴·링크로 이동할 때 본문 영역만 투명도 전환으로 사라지고 나타남 (헤더·푸터·배경 음악은 유지) ④ 마이크로 인터랙션: 카드 호버 시 살짝 떠오름·기울기와 포인트 색 테두리·아주 옅은 그림자, 버튼 누름 효과, 링크·메뉴 호버 색 전환. 투명도·위치(transform)만 움직여 레이아웃이 흔들리지 않고, 지속 시간은 짧게(대략 0.2~0.5초). 운영체제 "동작 줄이기" 설정 시 이동·기울기를 끄고 짧은 투명도 전환만 남김 | 사용자가 요청한 모던하고 세련된 UI/UX 경험. 게임 UI 같은 반응감으로 사이트 개성을 완성 | 모든 페이지 (공통 레이아웃: 헤더·본문 영역) |

### 3. MVP 이후 기능 (제외)

- 회원가입·로그인, 관리자 글쓰기 화면 (운영자는 저장소 파일로 작성)
- 댓글, 좋아요, 구독(RSS 포함)
- 전체 글 검색, 여러 태그 동시 필터, 시리즈 분류
- 프로젝트별 상세 페이지 (MVP는 카드의 외부 링크로 대신)
- 문의 폼, 이메일 공개
- 다국어 지원, 조회수 집계
- 코드 블록 복사 버튼·줄 번호·파일 이름 표시 (사용자 요청으로 제외)
- 게임 기록의 상태·플랫폼 필터, 게임별 상세 페이지, 여러 해를 합친 통계, 외부 게임 DB(API) 연동
- 배경 음악 음량 조절, 여러 곡 재생 목록(곡 넘기기·셔플), 페이지별 다른 음악, 켜짐 상태 기억·재방문 자동 재생 (사용자 결정으로 제외)
- 홈 히어로 타이핑·글리치 연출, 그 밖의 추가 연출(패럴랙스, 커서 효과 등) (이번에 고르지 않음)

### 4. ⚠️ 기술 검토 필요

| 요구 | 정적 사이트에서 안 되는 이유 | 대안 |
|------|---------------------------|------|
| 로그인 없이 운영자만 글 작성 | 서버 인증·DB가 없음 | 글을 저장소의 MDX 파일로 쓰고 푸시하면 GitHub Actions가 빌드·배포 (F011) |
| 영상 호스팅 | 큰 영상 파일을 저장소에 넣으면 GitHub 파일 크기·저장소 용량 제한에 걸리고 Pages 대역폭을 씀 | Supabase Storage 공개 버킷에 대시보드로 업로드하고 글에는 공개 URL만 적음. 사이트는 URL을 `<video>`로 읽기만 하므로 API 키·SDK 불필요 (F008) |
| 사진 자동 최적화 | 정적 내보내기에서는 Next.js 이미지 최적화 서버를 못 씀 | 이미지를 최적화 없이(unoptimized) 그대로 내보내고, 운영자가 올리기 전에 크기를 줄여(예: WebP, 가로 1600px 이하, 게임 표지는 가로 600px 이하) 저장 |
| 사이트에 들어오자마자 배경 음악 재생 | 정적 사이트 문제가 아니라 브라우저 자동 재생 정책 때문에, 방문자의 클릭·키 입력 전에는 소리 있는 재생이 막힘 | 헤더의 음악 켜기/끄기 버튼으로 방문자가 직접 켬. 방문마다 항상 꺼짐에서 시작하고 켜짐을 기억하지 않아 자동 재생 차단 문제가 생기지 않음. 같은 방문 안의 사이트 링크 이동에서만 이어서 재생 (F015) |
| 페이지가 "사라지고" 나타나는 전환 | 정적 사이트 문제는 아니지만, App Router는 페이지를 바꿀 때 이전 페이지를 바로 없애서 Motion의 퇴장(exit) 애니메이션이 안정적으로 동작하지 않음 | 기본은 새 페이지 본문이 투명도 전환으로 나타나는 등장 효과(Motion)로 구현. 사라지는 효과까지 필요하면 React `<ViewTransition>`(브라우저 View Transitions API, Next.js 16 App Router에서 설정 없이 동작) 크로스페이드를 검토하고, 지원하지 않는 브라우저는 즉시 전환 (F016, 프로젝트 React 버전 지원 여부는 ROADMAP 단계에서 확인) |

### 플레이 게임 기록 — `content/games/<연도>.json` (예: `content/games/2026.json`), JSON 배열 (표지는 `public/images/games/<연도>/`)

연도는 파일 이름에서 정한다. 파일 하나 = 연도 하나 = 플레이 게임 페이지 하나이며, 연도 선택 페이지의 연도 카드와 연도 전환 탭은 이 폴더의 파일 목록으로 만든다.

| 필드 | 설명 | 형식/관계 |
|------|------|----------|
| slug | 고유 식별자 (같은 연도 안에서 중복 금지) | 문자열 |
| title | 게임 제목 | 문자열 |
| cover | 표지 이미지 (선택) | 저장소 이미지 경로 |
| platforms | 플랫폼 (한 게임에 여러 개 가능) | PC / PS5 / Switch / Xbox / Mobile 등 문자열 배열 |
| status | 상태 | playing(플레이 중) / cleared(클리어) / dropped(중단) / wishlist(하고 싶은 게임) |
| rating | 평점 (선택, 하고 싶은 게임은 비움) | 1~5 정수 |
| comment | 한 줄 소감 (선택) | 문자열 |
| playtime | 플레이 시간 (선택) | 시간 단위 숫자 |
| startedAt | 시작일 (선택) | 날짜 (YYYY-MM-DD) |
| clearedAt | 클리어일 (선택, status가 cleared일 때만) | 날짜 (YYYY-MM-DD) |

### 배경 음악 — `content/music.json`, JSON (음원 파일은 `public/audio/`, 예: `public/audio/bgm.mp3`)

곡은 하나만 둔다. `music.json`이 없거나 `file`이 가리키는 mp3가 `public/audio/`에 없으면 빌드 시 "음원 없음"으로 판단해 헤더 버튼과 푸터 출처 문구를 숨긴다 (F015).

| 필드 | 설명 | 형식/관계 |
|------|------|----------|
| file | 음원 파일 이름 | `public/audio/` 안의 mp3 파일 이름 (예: bgm.mp3) |
| title | 곡 제목 (푸터 출처 문구) | 문자열 |
| artist | 작곡가·아티스트 (푸터 출처 문구) | 문자열 |
| source | 출처 이름 (예: YouTube 오디오 보관함, Pixabay) | 문자열 |
| sourceUrl | 곡 출처 페이지 링크 (선택, 새 탭) | URL |
| license | 라이선스 표기 (예: Pixabay Content License, 저작자 표시 필요 시 그 문구) | 문자열 |

방문자의 켜짐/꺼짐 상태는 저장하지 않는다 (localStorage 미사용). 방문마다 꺼짐에서 시작하고, 상태는 열려 있는 페이지의 메모리에만 있어 같은 방문 안의 사이트 링크 이동에서만 유지된다.

## 🛠️ 기술 스택

### 🎨 프론트엔드 프레임워크

- **TypeScript 5** - 타입 안전성 보장

### 🎨 스타일링 & UI

- **Tailwind CSS v4** (설정 파일 없음, 테마는 `app/globals.css`) - 유틸리티 CSS, 블랙 + 차분한 시안 1색 테마 변수 정의 (F012)
- **shadcn/ui** (Base UI 기반 `base-lyra` 스타일) - 컴포넌트 라이브러리 (Card, Badge, Avatar 등 재사용)
- **Lucide React** - 아이콘
- **next-themes** - 다크 모드 (기본값 다크)
- **simple-icons** - Unity, Unreal 등 기술 브랜드 아이콘 배지 (Lucide에 없는 로고용). 브랜드 색 대신 글자색(`currentColor`) 단색으로 그려 테마를 따라가고, 아이콘이 없는 기술(C# 등)은 텍스트 이니셜로 표시 (세부 방식은 T-202에서 확정)
- **Motion** (npm `motion`, 구 Framer Motion, `motion/react`에서 import) - F016 애니메이션 (사용자 선택). 첫 진입 스태거, 화면에 들어올 때 등장(`whileInView`, 한 번만), 페이지 본문 투명도 전환, 카드 호버 떠오름·기울기(`whileHover`)·버튼 누름(`whileTap`). 애니메이션이 필요한 조각만 `"use client"` 래퍼 컴포넌트(예: 등장·스태거·호버 카드 래퍼)로 만들어 `components/shared/`에 두고, 페이지·섹션은 서버 컴포넌트로 유지해 정적 내보내기를 그대로 씀. 루트에 `MotionConfig reducedMotion="user"`를 두어 "동작 줄이기" 설정 시 이동·기울기 애니메이션을 끔. 단순 색·밑줄 호버 전환은 Tailwind `transition`과 `motion-reduce:` 변형으로 처리
- (검토) **React `<ViewTransition>`** - 페이지가 사라지고 나타나는 크로스페이드가 Motion만으로 부족할 때 쓰는 대안 (추가 패키지 없음, 브라우저 View Transitions API 기반, `node_modules/next/dist/docs/01-app/02-guides/view-transitions.md` 참고)

### 📚 콘텐츠

- **next-mdx-remote** (RSC 방식) - `content/posts/`의 MDX를 빌드 시 렌더링, `Video` 같은 커스텀 컴포넌트 주입
- **gray-matter** - MDX frontmatter 읽기
- **rehype-pretty-code + shiki** - 코드 블록 하이라이트 (빌드 시 처리). 코드 블록에 붙는 언어 정보(`data-language`)로 패널 상단 언어 이름을 표시하고(`csharp`→C#, `cpp`→C++, `hlsl`→HLSL 같은 표시 이름 변환), 패널 배경·테두리는 F012 테마 변수로 정의 (복사 버튼용 클라이언트 코드 불필요)
- (게임 기록) **추가 라이브러리 없음** - JSON을 빌드 시 읽고, 카드·배지·탭은 기존 shadcn/ui(Card, Badge 등)와 Lucide 아이콘(별 평점 등)을 재사용. 데이터 형식 검증이 필요하면 이미 설치된 **Zod**로 빌드 시 검사
- **HTML `<video>` 요소** - 비디오 플레이어 (별도 라이브러리 없이 브라우저 기본 컨트롤)
- (배경 음악) **추가 라이브러리 없음** - 브라우저 기본 오디오(HTML `<audio>`, 반복 재생)를 루트 레이아웃의 클라이언트 Provider에 한 번만 두어 사이트 안 페이지 이동 시 끊기지 않게 함 (F016 페이지 전환 래퍼보다 바깥에 두어 전환 때 다시 그려지지 않게 함). 켜짐/꺼짐은 저장하지 않고 항상 꺼짐에서 시작. 버튼 아이콘은 Lucide(음표·음소거), 버튼은 기존 shadcn/ui Button 재사용. 음량·재생 목록이 필요해지는 MVP 이후에 Howler.js 같은 오디오 라이브러리를 검토

## 📝 가정과 미결 사항

### 결정됨

- **태그 필터 방식 (결정됨)**: "목록에서 태그로 걸러 보기"는 태그마다 빌드 시 별도 페이지(태그별 글 목록 페이지, `generateStaticParams`)를 만드는 방식으로 확정했다.
- **테마 색 (결정됨, 2026-11-09 변경)**: 처음 정한 시안 + 마젠타 네온 조합(글자·테두리 글로우)이 촌스럽다는 판단에 따라 "블랙 + 차분한 시안 1색"(Vercel·Linear 느낌)으로 바꿨다 (F012). 다크 기본값은 배경 약 #0A0A0B, 카드 약 #131316, 테두리 약 #26262B, 본문 약 #EDEDEF, 보조 글자 약 #8B8B93, 포인트 약 #5CC8D8. 마젠타와 글자 글로우(neon-text)는 없애고, 호버는 포인트 색 테두리 + 아주 옅은 그림자로 한다. 라이트 모드는 무채색 + 진한 시안 1색으로 맞추고, 두 모드 모두 명암비 WCAG AA 이상이어야 한다. 정확한 색 값(특히 라이트 모드 시안)은 구현 시 대비를 확인해 정한다. 404의 "GAME OVER" 같은 게임 개발 콘셉트 문구는 유지한다.
- **기술 스택 아이콘 (결정됨)**: simple-icons를 쓰고 브랜드 색 대신 글자색 단색으로 그려 테마를 따라가게 한다. 아이콘이 없는 기술(C# 등)은 텍스트 이니셜로 표시한다 (F002, 세부는 ROADMAP T-202에서 확정).
- **영상 호스팅 Supabase Storage (결정됨, 지침 예외)**: 사용자가 Supabase Storage 공개 버킷(읽기 전용, API 키 없음)을 명시적으로 선택해 확정했다. `prd-guide.md`의 "Supabase를 쓰지 않음"은 서버 DB·인증 용도를 막는 취지이며, 파일 호스팅 용도는 사용자 결정에 따른 예외로 둔다. DB·인증·SDK는 쓰지 않는다.
- **헤더 "게임"의 대상 (결정됨)**: 헤더 "게임"(`/games`)은 연도 카드 목록인 연도 선택 페이지이고, 연도 카드를 고르면 연도별 플레이 게임 페이지(`/games/<연도>`)로 이동한다. 정적 내보내기라 리디렉션 없이 링크로만 이동하며, 데이터 파일이 없는 연도는 404다 (F014, ROADMAP T-212·T-213).
- **표지 이미지 사용 방식 (결정됨)**: 게임 표지는 공식 스토어·보도자료 이미지를 가로 600px 이하로 줄여 쓰고, 플레이 게임 페이지 아래에 "표지 이미지 저작권은 각 게임사에 있습니다" 출처 문구를 표시한다. 문제가 되면 이니셜 자리표시로 대신한다.
- **배경 음악 방식 (결정됨)**: 브라우저 자동 재생 정책 때문에 들어오자마자 재생은 하지 않고, 헤더의 음악 켜기/끄기 버튼으로 방문자가 켠다. 다시 방문하면 항상 꺼짐에서 시작한다 (켜짐 상태를 기억해 자동 재생을 시도하지 않음). 같은 방문 안에서 사이트 링크(클라이언트 이동)로 페이지를 옮길 때만 이어서 재생하고, 새로고침·새 탭·주소 직접 입력은 새 방문처럼 꺼짐에서 시작한다 (재생 위치 기억도 하지 않음). 음원은 운영자가 저작권 무료 음원(YouTube 오디오 보관함, Pixabay 등)을 골라 mp3로 저장소에 넣고, 출처·라이선스는 푸터에 표시한다. 음원이 없으면 버튼을 숨긴다. 음량 조절·재생 목록은 MVP 이후 (F015).
- **UI 애니메이션 (결정됨)**: 첫 진입 연출(헤더 메뉴 스태거·홈 등장), 스크롤 등장, 페이지 전환(투명도), 카드·버튼 마이크로 인터랙션 4가지를 넣고, 라이브러리는 Motion(npm `motion`)으로 확정했다. 운영체제 "동작 줄이기" 설정을 따르고, 깔끔·짧게·레이아웃 흔들림 없이 만든다. 홈 히어로 타이핑·글리치 연출은 MVP 이후 (F016).

### 남은 확인 사항

- **Supabase 무료 플랜 한도**: 저장 용량과 전송량(egress) 한도를 넘으면 영상이 안 나올 수 있다. 영상은 압축(예: H.264 MP4, 1080p 이하)해서 올린다고 가정한다. 현재 무료 플랜 한도는 운영 전 확인한다.
- **MDX 라이브러리 (ROADMAP 단계 기술 확인)**: next-mdx-remote(RSC)를 제안했으나, Next.js 16·React 19 호환성은 ROADMAP 단계에서 확인한다. 안 되면 `@next/mdx` 또는 Velite 같은 빌드 시 콘텐츠 도구로 바꾼다.
- **simple-icons 사용 세부 (T-202에서 확인)**: 패키지 형태(simple-icons 본체 또는 React 래퍼), 라이선스(CC0)와 브랜드 상표 가이드라인, 아이콘이 빠진 기술 목록은 T-202 구현 시 확인한다.
- **기존 네온 스타일 정리**: 이미 구현된 neon-text 등 글로우 관련 스타일·클래스가 있다면 제거·교체가 필요하다 (소스 미확인, ROADMAP에서 작업으로 반영).
- **사진 경로와 basePath**: 사진은 `public/images/`에 두며, 나중에 `PAGES_BASE_PATH`를 쓰면 이미지 경로에 basePath를 붙이는 처리가 필요하다. 배경 음악 경로(`public/audio/`)도 같다.
- **첫 진입 연출의 범위**: 헤더 스태거는 페이지를 처음 불러올 때(첫 접속·새로고침)만 재생하고, 홈 등장 연출은 홈이 그려질 때마다(사이트 안에서 홈으로 돌아올 때 포함) 짧게 재생한다고 가정했다. 홈도 첫 진입에서만 보이게 바꿔도 된다.
- **페이지 전환의 "사라짐"**: App Router에서는 Motion의 퇴장 애니메이션이 안정적이지 않아, 기본은 새 페이지 본문이 투명도로 나타나는 효과로 구현한다고 가정했다. 이전 페이지가 흐려지는 크로스페이드는 React `<ViewTransition>`으로 검토하며, 프로젝트의 React 버전 지원 여부와 Motion과의 겹침은 ROADMAP 단계에서 확인한다 (문서 확인 필요).
- **JS 없이·느린 환경의 콘텐츠 표시**: 등장 효과는 처음에 투명도 0으로 그려지므로, 자바스크립트가 늦게 로드되면 잠깐 빈 화면이 보일 수 있다. 첫 화면(히어로·헤더)은 등장 거리를 작게, 지속 시간을 짧게 하고, 검색 엔진용 HTML에는 내용이 그대로 들어간다고 가정했다. 구현 시 확인한다.
- **카드 기울기 정도**: 호버 기울기는 마우스 위치를 따라 아주 작게(대략 수 도) 기울이고, 터치 기기에서는 기울기 없이 누름 효과만 쓴다고 가정했다.
- **음원 파일 크기·라이선스**: 한 곡을 반복 재생하는 짧은 루프 곡(예: 1~3분, 128kbps mp3, 수 MB 이하)을 가정했다. 저작자 표시가 필요한 라이선스면 `license`에 요구 문구를 그대로 적는다. 음원 선택과 라이선스 확인은 운영자 몫이다.
- **소개 데이터 형식**: 프로필·기술 스택·프로젝트·경력은 JSON 파일로 둔다고 가정했다 (TypeScript 상수 파일로 바꿔도 무방).
- **푸터 외부 링크**: 소개 페이지와 같은 `profile.json`의 `links`를 써서 중복 입력을 피한다고 가정했다.
- **게임 데이터 파일 구조**: 연도별 파일(`content/games/2026.json`)로 가정했다. 연도가 파일 이름에서 정해져 새해에는 파일 하나만 추가하면 된다. 단일 파일 + `year` 필드 방식으로 바꿔도 화면은 같다.
- **게임 기록 세부 규칙**: 평점은 1~5 정수(별 표시), 플레이 시간은 시간 단위, 플랫폼은 여러 개 허용, 한 해에 시작했거나 그해에 기록하고 싶은 게임을 그 연도 파일에 넣는다고 가정했다. 해를 넘겨 계속 플레이하는 게임은 다음 해 파일에도 다시 적는다.
- **푸터 "게임" 링크**: 헤더와 맞추기 위해 푸터에도 "게임"을 넣었다 (사용자 요청은 헤더만). 필요 없으면 빼도 정합성에 영향 없다.
- **코드 블록 언어 이름**: MDX 코드 블록에 언어를 적은 경우(예: ```` ```csharp ````)만 표시한다. 표시 이름 변환표(C#, C++, HLSL, GLSL, JSON 등)는 구현 시 정한다. 주요 하이라이트 언어(C#, C++, HLSL) 지원 여부는 ROADMAP 단계에서 shiki 언어 목록으로 확인한다.
