# 게임 개발자 개인 블로그 MVP PRD

> 작성일: 2026-11-08 · 지침: .claude/docs/prd-guide.md

## 🎯 핵심 정보

**목적**: 게임 개발자가 자신을 소개하고, 공부하고 개발한 내용을 글·사진·영상 포스트로 기록하고 보여 줄 개인 사이트를 만든다.
**사용자**: 운영자의 기술 스택·프로젝트·개발 기록을 보러 오는 채용 담당자, 동료 게임 개발자, 게임 개발을 공부하는 사람

## 🚶 사용자 여정

```
[홈 페이지]
    ↓ 첫 화면에서 한 줄 소개와 최근 글 확인
    ├─ "소개 보기" 클릭 / 헤더 "소개" ──→ [소개 페이지]
    └─ 최근 글 카드 클릭 / 헤더 "블로그" ──→ [블로그 목록 페이지] 또는 [글 상세 페이지]

[소개 페이지]
    ↓ 프로필·기술 스택·프로젝트·경력 타임라인 확인
    ├─ 외부 링크(GitHub, YouTube 등) 클릭 → 새 탭에서 외부 사이트
    └─ "블로그 보기" 클릭 → [블로그 목록 페이지]

[블로그 목록 페이지]
    ↓ 최신순 글 카드 훑어보기
    ├─ 글 카드 클릭 → [글 상세 페이지]
    └─ 태그 칩 클릭 → [태그별 글 목록 페이지]

[태그별 글 목록 페이지]
    ├─ 다른 태그 칩 클릭 → [태그별 글 목록 페이지] (다른 태그)
    ├─ "전체 글" 클릭 → [블로그 목록 페이지]
    └─ 글 카드 클릭 → [글 상세 페이지]

[글 상세 페이지]
    ↓ 본문·사진·영상 감상
    ├─ 본문의 태그 클릭 → [태그별 글 목록 페이지]
    ├─ 이전/다음 글 클릭 → [글 상세 페이지] (다른 글)
    └─ "목록으로" 클릭 → [블로그 목록 페이지]

[없는 주소로 접근] → [404 페이지] → "홈으로" 클릭 → [홈 페이지]
```

- 자동 리디렉션은 없다 (로그인·권한 분기 없음).
- 테마는 첫 방문 시 다크 모드, 방문자가 바꾸면 브라우저에 저장된 값을 따른다.

## ⚡ 기능 명세

### 1. MVP 핵심 기능

| ID | 기능명 | 설명 | MVP 필수 이유 | 관련 페이지 |
|----|--------|------|-------------|------------|
| **F001** | 자기소개 프로필 | 사진(선택), 이름, 한 줄 소개, 관심 분야, "지금 공부 중인 것" 목록 표시 | 사이트의 1순위 목적인 운영자 소개 | 소개 페이지 |
| **F002** | 기술 스택 배지 | 엔진·언어·도구를 분류별로 아이콘이 붙은 배지로 표시 | 게임 개발자의 역량을 한눈에 전달 | 소개 페이지 |
| **F003** | 프로젝트 카드·경력 타임라인 | 대표 프로젝트 카드(썸네일, 제목, 요약, 사용 기술, 외부 링크)와 경력·학력 세로 타임라인 | 실제 작업물과 이력 증명 | 소개 페이지 |
| **F004** | 외부 링크 목록 | GitHub, YouTube 등 외부 채널 링크 버튼(새 탭). 이메일·전화번호는 넣지 않음 | 방문자가 다른 채널로 이어지게 함 | 소개 페이지 |
| **F005** | 홈 하이라이트 | 네온 강조 히어로(이름·한 줄 소개·"소개 보기" 버튼)와 최근 글 3개 카드 | 첫 화면에서 정체성과 최신 활동 전달 | 홈 페이지 |
| **F006** | 글 목록 | 모든 글을 최신순 카드(썸네일, 제목, 요약, 작성일, 태그)로 표시 | 블로그 탐색의 시작점 | 블로그 목록 페이지 |
| **F007** | 글 본문 보기 | MDX 본문(제목, 작성일, 태그, 사진, 코드 블록 하이라이트)과 이전/다음 글 링크 | 개발 기록 전달의 핵심 | 글 상세 페이지 |
| **F008** | 영상 재생 | 글 안에 넣은 Supabase Storage 공개 URL 영상을 사이트의 비디오 플레이어(재생·일시정지·전체 화면 등 브라우저 기본 컨트롤)로 재생 | 게임 플레이·개발 결과는 영상이 가장 잘 보여 줌 | 글 상세 페이지 |
| **F009** | 태그별 글 걸러 보기 | 태그 하나를 고르면 그 태그가 붙은 글만 최신순으로 표시, 전체 태그 칩 목록 제공 | 주제별로 글을 찾는 유일한 수단 | 태그별 글 목록 페이지 |

### 2. MVP 필수 지원 기능

| ID | 기능명 | 설명 | MVP 필수 이유 | 관련 페이지 |
|----|--------|------|-------------|------------|
| **F010** | 공통 레이아웃·내비게이션 | 헤더 메뉴, 푸터(외부 링크), 모바일 메뉴, 다크/라이트 전환(기본 다크), 404 처리 | 모든 페이지를 오가기 위한 최소 구조 | 모든 페이지 |
| **F011** | 콘텐츠 불러오기 | 저장소의 MDX 글과 JSON 프로필 데이터를 빌드 시 읽어 페이지와 태그 목록을 만듦. 운영자는 파일을 커밋·푸시하면 반영 | 로그인·관리자 화면 없이 운영자만 작성 | 홈 페이지, 소개 페이지, 블로그 목록 페이지, 태그별 글 목록 페이지, 글 상세 페이지 |
| **F012** | 게임 개발자 테마 | 시안(주 포인트) + 마젠타(보조 포인트) 네온 조합의 포인트 색과 게임 UI 느낌의 글로우·테두리·호버 강조 효과를 다크/라이트 양쪽 테마 변수로 정의해 전 페이지에 적용 (라이트 모드는 대비를 위해 채도·밝기를 낮춘 시안·마젠타 사용) | 사용자가 요구한 사이트 개성의 핵심 | 모든 페이지 |

### 3. MVP 이후 기능 (제외)

- 회원가입·로그인, 관리자 글쓰기 화면 (운영자는 저장소 파일로 작성)
- 댓글, 좋아요, 구독(RSS 포함)
- 전체 글 검색, 여러 태그 동시 필터, 시리즈 분류
- 프로젝트별 상세 페이지 (MVP는 카드의 외부 링크로 대신)
- 문의 폼, 이메일 공개
- 다국어 지원, 조회수 집계

### 4. ⚠️ 기술 검토 필요

| 요구 | 정적 사이트에서 안 되는 이유 | 대안 |
|------|---------------------------|------|
| 로그인 없이 운영자만 글 작성 | 서버 인증·DB가 없음 | 글을 저장소의 MDX 파일로 쓰고 푸시하면 GitHub Actions가 빌드·배포 (F011) |
| 영상 호스팅 | 큰 영상 파일을 저장소에 넣으면 GitHub 파일 크기·저장소 용량 제한에 걸리고 Pages 대역폭을 씀 | Supabase Storage 공개 버킷에 대시보드로 업로드하고 글에는 공개 URL만 적음. 사이트는 URL을 `<video>`로 읽기만 하므로 API 키·SDK 불필요 (F008) |
| 사진 자동 최적화 | 정적 내보내기에서는 Next.js 이미지 최적화 서버를 못 씀 | 이미지를 최적화 없이(unoptimized) 그대로 내보내고, 운영자가 올리기 전에 크기를 줄여(예: WebP, 가로 1600px 이하) 저장 |

## 📱 메뉴 구조

```
📱 게임 개발자 블로그 헤더 메뉴 (config/site.ts의 mainNav)
├── 🏠 홈
│   └── 기능: F005 (히어로와 최근 글)
├── 📝 블로그
│   └── 기능: F006 (최신순 글 목록)
├── 👤 소개
│   └── 기능: F001, F002, F003, F004 (프로필·기술 스택·프로젝트·경력·외부 링크)
└── 🌓 다크/라이트 전환 - F010
(기존 스타터킷의 "컴포넌트" 데모 메뉴와 페이지는 제거)

🔗 푸터 메뉴
├── 블로그 - F006
├── 소개 - F001
└── 외부 링크: GitHub, YouTube - F010

➡️ 페이지 안 이동 (메뉴에 없는 페이지)
├── 홈 / 블로그 목록 / 태그별 글 목록 → 글 상세 페이지 - F007
├── 블로그 목록 / 글 상세 의 태그 칩 → 태그별 글 목록 페이지 - F009
├── 글 상세 → 이전/다음 글 상세 페이지 - F007
└── 없는 주소 → 404 페이지 - F010
```

## 📄 페이지별 상세 기능

### 홈 페이지

> **구현 기능:** `F005`, `F010`, `F011`, `F012` | **메뉴 위치:** 헤더 "홈", 로고 클릭

| 항목 | 내용 |
|------|------|
| **역할** | 랜딩 페이지. 운영자의 정체성과 최신 활동을 첫 화면에 보여 줌 |
| **진입 경로** | 사이트 첫 접속, 헤더 "홈"·로고 클릭, 404 페이지의 "홈으로" |
| **사용자 행동** | 히어로의 이름·한 줄 소개를 읽고, 최근 글을 고르거나 소개 페이지로 이동 |
| **주요 기능** | • 네온 강조 히어로(이름, 한 줄 소개, 지금 공부 중인 것 요약)<br>• 최근 글 3개 카드<br>• **소개 보기** 버튼, **전체 글 보기** 버튼 |
| **다음 이동** | 소개 보기 → 소개 페이지, 글 카드 → 글 상세 페이지, 전체 글 보기 → 블로그 목록 페이지 |

---

### 소개 페이지

> **구현 기능:** `F001`, `F002`, `F003`, `F004`, `F010`, `F011`, `F012` | **메뉴 위치:** 헤더 "소개", 푸터 "소개"

| 항목 | 내용 |
|------|------|
| **역할** | 운영자 소개. 누구이고 무엇을 할 수 있으며 무엇을 만들었는지 보여 줌 |
| **진입 경로** | 헤더·푸터 "소개", 홈의 "소개 보기" 버튼 |
| **사용자 행동** | 프로필과 기술 스택을 훑고, 프로젝트 카드와 타임라인을 읽고, 외부 채널로 이동 |
| **주요 기능** | • 프로필 영역: 사진(없으면 이니셜 아바타), 이름, 한 줄 소개, 관심 분야, 지금 공부 중인 것<br>• 기술 스택: 엔진 / 언어 / 도구 분류별 아이콘 배지<br>• 대표 프로젝트 카드(썸네일, 제목, 요약, 사용 기술 배지, 외부 링크)<br>• 경력·학력 세로 타임라인(기간, 이름, 소속, 설명)<br>• 외부 링크 버튼(GitHub, YouTube 등, 새 탭)<br>• **블로그 보기** 버튼 |
| **다음 이동** | 외부 링크·프로젝트 링크 → 새 탭 외부 사이트, 블로그 보기 → 블로그 목록 페이지 |

---

### 블로그 목록 페이지

> **구현 기능:** `F006`, `F010`, `F011`, `F012` | **메뉴 위치:** 헤더 "블로그", 푸터 "블로그"

| 항목 | 내용 |
|------|------|
| **역할** | 모든 글을 모아 보는 블로그의 시작점 |
| **진입 경로** | 헤더·푸터 "블로그", 홈의 "전체 글 보기", 글 상세·태그별 목록의 "목록으로/전체 글" |
| **사용자 행동** | 최신순 글 카드를 훑고 읽을 글이나 관심 태그를 고름 |
| **주요 기능** | • 최신순 글 카드 목록(썸네일, 제목, 요약, 작성일, 태그 칩, 영상 포함 표시)<br>• 상단에 전체 태그 칩 목록(태그별 글 수)<br>• 글이 없을 때 "아직 글이 없습니다" 안내 |
| **다음 이동** | 글 카드 → 글 상세 페이지, 태그 칩 → 태그별 글 목록 페이지 |

---

### 태그별 글 목록 페이지

> **구현 기능:** `F009`, `F010`, `F011`, `F012` | **메뉴 위치:** 메뉴에 없음 (태그 칩으로 진입)

| 항목 | 내용 |
|------|------|
| **역할** | 선택한 태그의 글만 모아 보여 줌 (태그마다 빌드 시 한 페이지씩 생성) |
| **진입 경로** | 블로그 목록·글 상세의 태그 칩 클릭 |
| **사용자 행동** | 같은 주제의 글을 훑고, 다른 태그로 바꾸거나 전체 목록으로 돌아감 |
| **주요 기능** | • 현재 태그 이름과 글 수 표시<br>• 해당 태그 글의 최신순 카드 목록<br>• 전체 태그 칩 목록(현재 태그 네온 강조)<br>• **전체 글** 버튼 |
| **다음 이동** | 글 카드 → 글 상세 페이지, 다른 태그 칩 → 태그별 글 목록 페이지, 전체 글 → 블로그 목록 페이지, 없는 태그 → 404 페이지 |

---

### 글 상세 페이지

> **구현 기능:** `F007`, `F008`, `F010`, `F011`, `F012` | **메뉴 위치:** 메뉴에 없음 (글 카드로 진입)

| 항목 | 내용 |
|------|------|
| **역할** | 콘텐츠 상세. 글·사진·영상으로 된 개발 기록을 읽고 봄 |
| **진입 경로** | 홈·블로그 목록·태그별 글 목록의 글 카드, 다른 글의 이전/다음 링크 |
| **사용자 행동** | 본문을 읽고, 사진과 영상을 보고, 관련 태그나 다른 글로 이동 |
| **주요 기능** | • 제목, 작성일, 태그 칩, 대표 이미지<br>• MDX 본문(제목 단계, 목록, 인용, 사진, 코드 블록 하이라이트)<br>• 본문 안 비디오 플레이어(Supabase 공개 URL, 기본 컨트롤, 포스터 이미지 선택)<br>• 이전/다음 글 링크<br>• **목록으로** 버튼 |
| **다음 이동** | 태그 칩 → 태그별 글 목록 페이지, 이전/다음 → 글 상세 페이지, 목록으로 → 블로그 목록 페이지, 없는 글 → 404 페이지 |

---

### 404 페이지

> **구현 기능:** `F010`, `F012` | **메뉴 위치:** 메뉴에 없음 (없는 주소 접근 시)

| 항목 | 내용 |
|------|------|
| **역할** | 없는 주소 안내 (게임 "GAME OVER" 느낌의 연출) |
| **진입 경로** | 존재하지 않는 글·태그·주소로 접근 |
| **사용자 행동** | 안내를 보고 홈이나 블로그로 돌아감 |
| **주요 기능** | • 페이지를 찾을 수 없다는 안내 문구<br>• **홈으로** 버튼, **블로그 보기** 버튼 |
| **다음 이동** | 홈으로 → 홈 페이지, 블로그 보기 → 블로그 목록 페이지 |

## 📝 가정과 미결 사항

### 결정됨

- **태그 필터 방식 (결정됨)**: "목록에서 태그로 걸러 보기"는 태그마다 빌드 시 별도 페이지(태그별 글 목록 페이지, `generateStaticParams`)를 만드는 방식으로 확정했다.
- **네온 포인트 색 (결정됨)**: 시안(주 포인트) + 마젠타(보조 포인트) 네온 조합으로 확정했다 (F012). 구체적인 색 값은 구현 시 다크/라이트 양쪽 대비(WCAG)를 확인해 정한다.
- **영상 호스팅 Supabase Storage (결정됨, 지침 예외)**: 사용자가 Supabase Storage 공개 버킷(읽기 전용, API 키 없음)을 명시적으로 선택해 확정했다. `prd-guide.md`의 "Supabase를 쓰지 않음"은 서버 DB·인증 용도를 막는 취지이며, 파일 호스팅 용도는 사용자 결정에 따른 예외로 둔다. DB·인증·SDK는 쓰지 않는다.

### 남은 확인 사항

- **Supabase 무료 플랜 한도**: 저장 용량과 전송량(egress) 한도를 넘으면 영상이 안 나올 수 있다. 영상은 압축(예: H.264 MP4, 1080p 이하)해서 올린다고 가정한다. 현재 무료 플랜 한도는 운영 전 확인한다.
- **MDX 라이브러리 (ROADMAP 단계 기술 확인)**: next-mdx-remote(RSC)를 제안했으나, Next.js 16·React 19 호환성은 ROADMAP 단계에서 확인한다. 안 되면 `@next/mdx` 또는 Velite 같은 빌드 시 콘텐츠 도구로 바꾼다.
- **기술 브랜드 아이콘 라이브러리 (ROADMAP 단계 기술 확인)**: Unity, Unreal, C# 등 Lucide에 없는 로고용 아이콘 라이브러리(simple-icons 계열 등) 선택과 라이선스는 ROADMAP 단계에서 확인한다.
- **사진 경로와 basePath**: 사진은 `public/images/`에 두며, 나중에 `PAGES_BASE_PATH`를 쓰면 이미지 경로에 basePath를 붙이는 처리가 필요하다.
- **소개 데이터 형식**: 프로필·기술 스택·프로젝트·경력은 JSON 파일로 둔다고 가정했다 (TypeScript 상수 파일로 바꿔도 무방).
- **푸터 외부 링크**: 소개 페이지와 같은 `profile.json`의 `links`를 써서 중복 입력을 피한다고 가정했다.
