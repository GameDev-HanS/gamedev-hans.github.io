# 게임 개발자 개인 블로그 MVP PRD

> 작성일: 2026-11-08 · 수정일: 2026-11-09 (테마를 블랙 + 시안 1색으로 변경, T-218: 게임 PV 팝업·/games 구조 변경, T-219: /games 전체 보기·earlier.json·한글 플랫폼 표기) · 수정일: 2026-11-12 (T-220: 게임 목록 바 형태·PV 안내 문구, 유튜브 썸네일 미사용 확정) · 수정일: 2026-11-13 (소개 페이지를 없애고 홈에 통합·헤더 메뉴 3개, 실제 데이터로 교체, skills 분류 5개·timeline `certificate`, 기술 배지를 테마색 + 브랜드 색 아이콘으로 변경) · 지침: .claude/docs/prd-guide.md

## 🎯 핵심 정보

**목적**: 게임 개발자가 자신을 소개하고, 공부하고 개발한 내용을 글·사진·영상 포스트로, 좋아하고 플레이 중인 게임을 연도별 기록으로 남기고 보여 줄 개인 사이트를 만든다.
**사용자**: 운영자의 기술 스택·프로젝트·개발 기록을 보러 오는 채용 담당자, 동료 게임 개발자, 게임 개발을 공부하는 사람

## 🚶 사용자 여정

```
[홈 페이지]
    ↓ 첫 화면의 히어로('HanS Dev Log')를 보고 아래로 스크롤하며 프로필 → 기술 스택 → 경력·학력 → 자격증 → 최근 글을 차례로 확인 (별도 소개 페이지 없음)
    ├─ "전체 글 보기" 클릭 / 헤더 "블로그" ──→ [블로그 목록 페이지]
    ├─ 최근 글 카드 클릭 ──→ [글 상세 페이지]
    └─ 헤더 "게임" ──→ [플레이 게임 페이지] (/games, 전체 보기)

[플레이 게임 페이지]
    ↓ /games에서 바로 지금까지 플레이한 모든 게임(2026 이전 포함)을 상태별로 확인 (연도를 고르는 중간 페이지 없음)
    ├─ 제목 아래 보기 목록(전체 · 2026 · 2025 …)에서 연도 클릭 → [플레이 게임 페이지] (/games/<연도>, 그해 플레이한 게임만)
    ├─ 보기 목록에서 "전체" 클릭 / 헤더 "게임" 클릭 → [플레이 게임 페이지] (/games, 전체 보기)
    ├─ ▶ PV 표시가 있는 게임 줄 클릭 → [PV 팝업] (유튜브 PV 재생)
    │     ├─ "YouTube에서 보기" 클릭 → 새 탭에서 유튜브
    │     └─ 닫기(× 버튼·Esc·바깥 클릭) → 재생 멈추고 게임 목록으로
    └─ 없는 연도로 접근 → [404 페이지]

[블로그 목록 페이지]
    ↓ 최신순 글 카드 훑어보기
    ├─ 글 카드 클릭 → [글 상세 페이지]
    └─ 태그 칩 클릭 → [태그별 글 목록 페이지]

[태그별 글 목록 페이지]
    ├─ 다른 태그 칩 클릭 → [태그별 글 목록 페이지] (다른 태그)
    ├─ "전체 글" 클릭 → [블로그 목록 페이지]
    └─ 글 카드 클릭 → [글 상세 페이지]

[글 상세 페이지]
    ↓ 본문·사진·영상 감상
    ├─ 본문의 태그 클릭 → [태그별 글 목록 페이지]
    ├─ 이전/다음 글 클릭 → [글 상세 페이지] (다른 글)
    └─ "목록으로" 클릭 → [블로그 목록 페이지]

[없는 주소로 접근] → [404 페이지] → "홈으로" 클릭 → [홈 페이지]

[모든 페이지 공통 — 헤더 배경 음악 버튼 (음원 파일이 있을 때만 보임)]
    ↓ 방문할 때마다 항상 꺼짐 상태에서 시작
    ├─ 버튼 클릭 (꺼짐 → 켜짐) → 배경 음악 반복 재생
    │     └─ 헤더·카드·탭 등 사이트 안 링크로 다른 페이지 이동 → 음악이 끊기지 않고 이어서 재생
    ├─ 버튼 다시 클릭 (켜짐 → 꺼짐) → 음악 정지
    └─ 다음 방문·새로고침·새 탭·주소 직접 입력 → 다시 꺼짐에서 시작 (켜짐을 기억하거나 자동 재생을 시도하지 않음)

[모든 페이지 공통 — UI 애니메이션 (F016)]
    ↓ 사이트에 처음 들어옴 (첫 접속·새로고침)
    ├─ 헤더 메뉴 항목이 왼쪽부터 차례로 나타남 (투명도·위치 전환) → 홈이면 히어로도 차례로 등장 (그 아래 프로필·기술 스택·경력·자격증·최근 글은 스크롤하면 등장)
    ├─ 아래로 스크롤 → 카드·섹션이 화면에 들어올 때 아래에서 살짝 올라오며 나타남 (한 번만)
    ├─ 헤더·카드·탭 등으로 페이지 이동 → 이전 페이지가 흐려지고 새 페이지가 부드럽게 나타남 (헤더·푸터는 그대로)
    ├─ 카드·버튼·링크에 마우스 올림 → 카드가 살짝 떠오르고 기울며 테두리가 포인트 색(시안)으로 바뀜, 링크·메뉴 색 전환
    └─ 운영체제 "동작 줄이기" 설정 → 이동·기울기 없이 짧은 투명도 전환만 (또는 즉시 표시)
```

- 자동 리디렉션은 없다 (로그인·권한 분기 없음).
- 테마는 첫 방문 시 다크 모드, 방문자가 바꾸면 브라우저에 저장된 값을 따른다.
- 배경 음악은 방문할 때마다 꺼짐에서 시작하고, 켜고 끈 선택은 저장하지 않는다. 같은 방문 안에서 사이트 링크로 이동할 때만 이어서 재생한다 (F015).
- 애니메이션은 방문자의 운영체제 "동작 줄이기" 설정을 따른다 (F016).

## ⚡ 기능 명세

### 1. MVP 핵심 기능

| ID | 기능명 | 설명 | MVP 필수 이유 | 관련 페이지 |
|----|--------|------|-------------|------------|
| **F001** | 자기소개 프로필 | **홈의 프로필 섹션**. 사진(선택, 세로 3:4 비율의 각진 네모), 이름(김한승 — 사용자가 실명 공개를 결정), 한 줄 소개, 관심 분야, "지금 공부 중인 것" 목록 표시. 사진이 없으면 이름 첫 글자 이니셜 아바타 | 사이트의 1순위 목적인 운영자 소개 | 홈 페이지 |
| **F002** | 기술 스택 배지 | **홈의 기술 스택 섹션**. 언어 / 게임 엔진 / 운영체제 / IDE / 기타 5개 묶음으로, 기술마다 어두운 테마색 배지에 브랜드 색 아이콘(simple-icons)과 이름을 표시. 브랜드 색이 배경에 묻히는 경우(상대 휘도 0.05 미만은 다크 모드, 0.4 초과는 라이트 모드)에는 그 모드에서 아이콘을 글자색으로 표시. 아이콘이 없는 기술(C#, Windows, VSCode, Visual Studio)은 이름 첫 글자 칸으로 표시 | 게임 개발자의 역량을 한눈에 전달 | 홈 페이지 |
| **F003** | 경력·학력 타임라인과 자격증 | **홈의 경력·학력 섹션**(세로 타임라인: 경력·교육 3건, 기간·직함·소속·설명, 구분은 아이콘·라벨)과 **자격증 섹션**(자격증 1건, `timeline.json`의 `certificate` 항목을 별도 섹션으로 표시). 대표 프로젝트 카드(썸네일, 제목, 요약, 사용 기술, 외부 링크)는 `projects.json`이 빈 배열이라 지금은 화면에 없음 (프로젝트가 생기면 다시 검토 — "가정과 미결 사항" 참고) | 이력과 자격 증명 | 홈 페이지 |
| **F004** | 외부 링크 목록 | GitHub, solved.ac 등 외부 채널 링크를 `profile.json`의 `links`에 데이터로 둠(http/https만, 이메일·전화번호는 넣지 않음). **홈에는 외부 링크 버튼이 없고**, 푸터의 외부 링크(GitHub 등, 새 탭)로만 보임 | 방문자가 다른 채널로 이어지게 함 | 공통 레이아웃(푸터) |
| **F005** | 홈 하이라이트 | 포인트 색(시안)으로 강조한 히어로(사이트 이름 'HanS Dev Log'·설명·"전체 글 보기" 버튼만)와, 프로필·기술 스택·경력·학력·자격증 섹션 아래의 최근 글 3개 카드. 홈 순서: 히어로 → 프로필 → 기술 스택 → 경력·학력 → 자격증 → 최근 글 | 첫 화면에서 정체성과 최신 활동 전달 | 홈 페이지 |
| **F006** | 글 목록 | 모든 글을 최신순 카드(썸네일, 제목, 요약, 작성일, 태그)로 표시 | 블로그 탐색의 시작점 | 블로그 목록 페이지 |
| **F007** | 글 본문 보기 | MDX 본문(제목, 작성일, 태그, 사진, 코드 블록)과 이전/다음 글 링크. 코드 블록은 본문과 구분되는 전용 배경 패널에 문법 하이라이트로 보여 주고, 패널 상단에 언어 이름(C#, C++, HLSL 등)을 표시 (복사 버튼·줄 번호·파일 이름은 없음) | 개발 기록 전달의 핵심 (코드가 본문과 섞이지 않아야 읽기 쉬움) | 글 상세 페이지 |
| **F008** | 영상 재생 | 글 안에 넣은 Supabase Storage 공개 URL 영상을 사이트의 비디오 플레이어(재생·일시정지·전체 화면 등 브라우저 기본 컨트롤)로 재생 | 게임 플레이·개발 결과는 영상이 가장 잘 보여 줌 | 글 상세 페이지 |
| **F009** | 태그별 글 걸러 보기 | 태그 하나를 고르면 그 태그가 붙은 글만 최신순으로 표시, 전체 태그 칩 목록 제공 | 주제별로 글을 찾는 유일한 수단 | 태그별 글 목록 페이지 |
| **F013** | 플레이 게임 목록 (바 형태) | 선택한 보기(전체 또는 한 연도)의 게임을 상태별(플레이 중 → 클리어 → 중단 → 하고 싶은 게임) 묶음 안에 **한 줄(바) 형태 목록**으로 표시 (데스크톱 2열, 모바일 1열). 한 줄은 왼쪽 작은 칸(표지가 있으면 작은 표지, 없으면 제목 이니셜), 제목·상태 배지, 플레이 시간·날짜(시작일, 끝낸 날)·플랫폼(한글 표기: "PC (Steam)", "PC", "모바일" 등, 여러 개 가능), 오른쪽 ▶ PV 표시(PV가 있을 때만)로 이루어짐 (값이 없는 항목은 숨김. 상태가 없는 게임은 상태 배지 없이 표시). 세로 표지 카드는 쓰지 않음 (사용자 결정, 2026-11-12, T-220) | 운영자가 어떤 게임을 좋아하고 플레이 중인지 보여 주는 새 페이지의 본체 | 플레이 게임 페이지 |
| **F014** | 전체·연도별 게임 기록 전환 | 헤더 "게임"(`/games`)을 누르면 연도를 고르는 중간 페이지 없이 바로 **전체 보기**(지금까지 플레이한 모든 게임, 2026 이전 포함)를 보여 줌. 전체 보기는 모든 연도 파일과 `earlier.json`을 합치며, 같은 게임(slug)이 여러 파일에 있으면 가장 최근 연도 것 하나만 보여 줌(`earlier.json`은 어느 연도보다 이전으로 취급). 페이지 제목 아래 보기 목록(전체 · 2026 · 2025 …, "전체"가 맨 앞, 연도는 데이터 파일이 있는 연도만 최신순)으로 오가며, 연도를 누르면 `/games/<연도>`에서 그해 플레이한 게임만 보여 줌. `/games`와 `/games/<연도>`는 내용이 달라 canonical 처리는 하지 않고, sitemap에는 `/games`와 모든 `/games/<연도>`를 넣음. 연도마다 빌드 시 페이지를 하나씩 만들고(2026년부터), 없는 연도는 404. `earlier.json`은 연도 페이지가 없고 전체 보기에만 나옴. 새 연도는 데이터 파일만 추가하면 보기 목록·페이지가 늘어남 | 해마다 기록이 쌓여도 전체 기록과 지난 기록을 함께 볼 수 있어야 함 (사용자 결정, T-219) | 플레이 게임 페이지 |
| **F017** | 게임 PV 팝업 재생 | 게임사 공식 유튜브 PV(`trailer`)가 있는 게임 줄(▶ PV 표시)을 누르면 팝업(다이얼로그)에서 PV를 재생. 게임 목록 위에 안내 문구 "PV 표시가 있는 게임을 누르면 공식 PV(YouTube)가 팝업으로 재생됩니다. 누르기 전에는 YouTube에 연결하지 않습니다."를 표시. `youtube-nocookie.com` 임베드를 쓰고, 팝업이 열렸을 때만 iframe을 그려 누르기 전에는 유튜브로 요청이 가지 않음 (유튜브 썸네일 이미지도 쓰지 않음). 팝업을 닫으면 iframe을 없애 재생을 멈춤. 팝업 아래 "YouTube에서 보기" 링크(새 탭, 연령 제한 등으로 임베드가 안 되는 경우 대비). PV가 없는 줄은 누를 수 없는 일반 줄. 영상 파일은 저장소에 올리지 않음 | 표지 이미지 저작권 문제 없이 게임을 생생하게 보여 주는 수단 (사용자 결정, T-218) | 플레이 게임 페이지 |

### 2. MVP 필수 지원 기능

| ID | 기능명 | 설명 | MVP 필수 이유 | 관련 페이지 |
|----|--------|------|-------------|------------|
| **F010** | 공통 레이아웃·내비게이션 | 헤더 메뉴, 푸터(저작권 표시·외부 링크, 사이트 안 메뉴 링크는 헤더와 겹쳐 두지 않음), 모바일 메뉴, 다크/라이트 전환(기본 다크), 404 처리 | 모든 페이지를 오가기 위한 최소 구조 | 모든 페이지 |
| **F011** | 콘텐츠 불러오기 | 저장소의 MDX 글, JSON 프로필 데이터, 연도별 게임 기록 JSON과 `earlier.json`을 빌드 시 읽어 페이지·태그 목록·게임 보기 목록(전체·연도)을 만듦. 운영자는 파일을 커밋·푸시하면 반영 | 로그인·관리자 화면 없이 운영자만 작성 | 홈 페이지, 블로그 목록 페이지, 태그별 글 목록 페이지, 글 상세 페이지, 플레이 게임 페이지 |

### 4. ⚠️ 기술 검토 필요

| 요구 | 정적 사이트에서 안 되는 이유 | 대안 |
|------|---------------------------|------|
| 로그인 없이 운영자만 글 작성 | 서버 인증·DB가 없음 | 글을 저장소의 MDX 파일로 쓰고 푸시하면 GitHub Actions가 빌드·배포 (F011) |
| 영상 호스팅 | 큰 영상 파일을 저장소에 넣으면 GitHub 파일 크기·저장소 용량 제한에 걸리고 Pages 대역폭을 씀 | Supabase Storage 공개 버킷에 대시보드로 업로드하고 글에는 공개 URL만 적음. 사이트는 URL을 `<video>`로 읽기만 하므로 API 키·SDK 불필요 (F008) |
| 사진 자동 최적화 | 정적 내보내기에서는 Next.js 이미지 최적화 서버를 못 씀 | 이미지를 최적화 없이(unoptimized) 그대로 내보내고, 운영자가 올리기 전에 크기를 줄여(예: WebP, 가로 1600px 이하, 게임 표지는 가로 600px 이하) 저장 |
| 게임 PV 영상 표시 | 게임사 PV 영상 파일을 저장소에 올리면 저작권·저장소 용량 문제가 생기고, 유튜브 임베드를 페이지에 바로 두면 방문하자마자 유튜브로 요청(쿠키·추적)이 감 | 영상 파일은 올리지 않고 데이터에 유튜브 영상 ID(`trailer`)만 적음. 게임 줄을 눌러 팝업이 열렸을 때만 `youtube-nocookie.com` iframe을 그려 누르기 전에는 유튜브 요청이 없고, 닫으면 iframe을 없애 재생을 멈춤. 연령 제한 등으로 임베드가 막힌 영상은 팝업 아래 "YouTube에서 보기" 링크로 대신 (F017) |
| `/games` 전체 보기와 연도별 보기 | 정적 내보내기라 요청 시 서버에서 데이터를 합치거나 걸러 줄 수 없음 | 빌드 시 모든 연도 파일과 `earlier.json`을 읽어 `/games`(전체, slug 중복은 가장 최근 연도 것만)와 `/games/<연도>`(그해 파일만, `generateStaticParams`)를 각각 정적 페이지로 생성. 두 페이지 내용이 달라 canonical 불필요, sitemap에는 `/games`와 모든 `/games/<연도>`를 넣음 (F014) |
| 사이트에 들어오자마자 배경 음악 재생 | 정적 사이트 문제가 아니라 브라우저 자동 재생 정책 때문에, 방문자의 클릭·키 입력 전에는 소리 있는 재생이 막힘 | 헤더의 음악 켜기/끄기 버튼으로 방문자가 직접 켬. 방문마다 항상 꺼짐에서 시작하고 켜짐을 기억하지 않아 자동 재생 차단 문제가 생기지 않음. 같은 방문 안의 사이트 링크 이동에서만 이어서 재생 (F015) |
| 페이지가 "사라지고" 나타나는 전환 | 정적 사이트 문제는 아니지만, App Router는 페이지를 바꿀 때 이전 페이지를 바로 없애서 Motion의 퇴장(exit) 애니메이션이 안정적으로 동작하지 않음 | 기본은 새 페이지 본문이 투명도 전환으로 나타나는 등장 효과(Motion)로 구현. 사라지는 효과까지 필요하면 React `<ViewTransition>`(브라우저 View Transitions API, Next.js 16 App Router에서 설정 없이 동작) 크로스페이드를 검토하고, 지원하지 않는 브라우저는 즉시 전환 (F016, 프로젝트 React 버전 지원 여부는 ROADMAP 단계에서 확인) |

### 플레이 게임 페이지

> **구현 기능:** `F013`, `F014`, `F017`, `F010`, `F011`, `F012`, `F015`, `F016` | **메뉴 위치:** 헤더 "게임" (`/games` = 전체, 연도별은 `/games/<연도>`)

| **사용자 행동** | 상태별 게임 목록(한 줄씩)을 훑으며 무엇을 하고 있고 어떻게 평가했는지 보고, PV가 있는 게임은 눌러서 영상을 보고, 전체와 연도별 보기를 오감 |
| **주요 기능** | • 페이지 제목(전체 또는 연도)과 상태별 게임 수 요약(플레이 중 n · 클리어 n · 중단 n · 하고 싶은 게임 n)<br>• 제목 아래 보기 목록(전체 · 2026 · 2025 …, "전체"가 맨 앞, 연도는 데이터 파일이 있는 연도만 최신순, 현재 보기는 포인트 색으로 강조). ## 🗄️ 데이터 모델 (콘텐츠 구조)

### 글 (블로그 포스트) — `content/posts/`, MDX (사진은 `public/images/posts/<slug>/`)

| 필드 | 설명 | 형식/관계 |
|------|------|----------|
| slug | 고유 식별자 (파일 이름) | 문자열 |
| title | 글 제목 | 문자열 |
| date | 작성일 (목록 정렬 기준) | 날짜 (YYYY-MM-DD) |
| summary | 카드에 보일 요약 | 문자열 |
| tags | 태그 목록 (태그 페이지는 여기서 모아 만듦) | 문자열 배열 |
| thumbnail | 대표 이미지 (선택) | 저장소 이미지 경로 |

본문의 영상은 MDX 컴포넌트로 넣음: `<Video src="<Supabase 공개 URL>" poster="<이미지 경로(선택)>" />`

### 프로필 (자기소개) — `content/profile.json`, JSON

| 필드 | 설명 | 형식/관계 |
|------|------|----------|
| name | 이름(또는 닉네임) | 문자열 |
| tagline | 한 줄 소개 | 문자열 |
| photo | 프로필 사진 (선택, `/images/profile/` 아래 경로, 적었는데 파일이 없으면 빌드 실패). 원본 비율(세로 3:4)의 각진 네모로 표시, 현재 `profile.webp`(300×400, 메타데이터 없음) | 저장소 이미지 경로 |
| interests | 관심 분야 | 문자열 배열 |

### 플레이 게임 기록 — `content/games/<연도>.json` (예: `content/games/2026.json`) + `content/games/earlier.json`, JSON 배열 (표지는 `public/images/games/<연도>/`, earlier는 `public/images/games/earlier/`)

연도는 파일 이름에서 정한다. 연도 파일 하나 = 연도 하나 = `/games/<연도>` 페이지 하나이며, 보기 목록의 연도는 이 폴더의 연도 파일 목록으로 정한다.

- `earlier.json`: 2026 이전에만 플레이해 정확한 연도가 없는 게임. 연도 페이지와 보기 목록에는 없고 전체 보기(`/games`)에만 나온다 (파일이 없어도 됨).
- 해를 넘겨 이어서 플레이한 게임(예: 2026 이전 ~ 2026)은 그해 파일(`2026.json`)에 넣는다.
- 전체 보기는 모든 파일을 합치고, 같은 slug가 여러 파일에 있으면 가장 최근 연도 파일의 항목 하나만 쓴다 (`earlier.json`은 어느 연도보다 이전).
- 끝나지 않은 게임(기간 '2026 ~')은 `status` 없이 기록한다. 운영자가 플레이 중이라고 명시한 게임만 `playing`으로 적는다.

| 필드 | 설명 | 형식/관계 |
|------|------|----------|
| slug | 고유 식별자 (같은 파일 안에서 중복 금지, 여러 파일에 같은 게임이면 같은 slug) | 문자열 |
| title | 게임 제목 | 문자열 |
| cover | 표지 이미지 (선택) | `/images/games/<연도>/` 아래 실제로 있는 파일 경로 |
| coverCredit | 표지 출처 문구 (cover가 있으면 필수) | 문자열 |
| trailer | 게임사 공식 유튜브 PV 영상 ID (선택, 있으면 게임 줄을 눌러 팝업 재생, F017) | 유튜브 영상 ID 11자 (영문·숫자·`-`·`_`, URL이 아닌 ID만) |
| platforms | 플랫폼 (한 게임에 여러 개 가능, 한글 표기를 그대로 배지에 표시) | "PC (Steam)" / "PC" / "모바일" 등 문자열 배열 |
| status | 상태 (선택, 없으면 상태 배지 없이 표시) | playing(플레이 중) / cleared(클리어) / dropped(중단) / wishlist(하고 싶은 게임) |
| rating | 평점 (선택, 하고 싶은 게임은 비움) | 1~5 정수 |
| comment | 한 줄 소감 (선택) | 문자열 |
| playtime | 플레이 시간 (선택) | 시간 단위 숫자 |
| startedAt | 시작일 (선택) | 날짜 (YYYY-MM-DD) |
| endedAt | 끝낸 날 (선택, 클리어 여부와 관계없이 그만둔 날도 포함) | 날짜 (YYYY-MM-DD) |

빌드 시 검증 규칙 (Zod): 표에 없는 필드가 있으면 빌드 실패(오타 방지), `endedAt`이 `startedAt`보다 이르면 빌드 실패, `cover`가 있는데 파일이 없거나 `coverCredit`이 없으면 빌드 실패, `trailer`가 11자 유튜브 영상 ID 형식(`[A-Za-z0-9_-]{11}`)이 아니면 빌드 실패. 상태와 날짜는 서로 강제하지 않는다 (예: playing인데 `endedAt`이 있어도 허용, 날짜가 모두 없는 게임도 허용).

빌드 시 검증 대상은 연도 파일과 `earlier.json` 모두이고, 같은 파일 안 slug 중복은 빌드 실패다.

현재 데이터 (2026-11-09, T-219): `content/games/2026.json`에 18개, `content/games/earlier.json`에 4개(DJMAX RESPECT V, 몬스터 헌터: 월드 - 아이스본, 배틀그라운드, 이터널 리턴)가 있고, 게임마다 공식 PV(`trailer`)가 연결되어 있다. 끝나지 않은 게임은 status 없이 기록되어 있다 (rating·comment는 비어 있음, 날짜가 없는 게임도 있음).

### 배경 음악 — `content/music.json`, JSON (음원 파일은 `public/audio/`, 예: `public/audio/bgm.mp3`)

곡은 하나만 둔다. `music.json`이 없거나 `file`이 가리키는 mp3가 `public/audio/`에 없으면 빌드 시 "음원 없음"으로 판단해 헤더 버튼과 푸터 출처 문구를 숨긴다 (F015).

| 필드 | 설명 | 형식/관계 |
|------|------|----------|
| file | 음원 파일 이름 | `public/audio/` 안의 mp3 파일 이름 (예: bgm.mp3) |
| title | 곡 제목 (푸터 출처 문구) | 문자열 |
| artist | 작곡가·아티스트 (푸터 출처 문구) | 문자열 |
| source | 출처 이름 (예: YouTube 오디오 보관함, Pixabay) | 문자열 |
| sourceUrl | 곡 출처 페이지 링크 (선택, 새 탭) | URL |
| license | 라이선스 표기 (예: Pixabay Content License, 저작자 표시 필요 시 그 문구) | 문자열 |

방문자의 켜짐/꺼짐 상태는 저장하지 않는다 (localStorage 미사용). 방문마다 꺼짐에서 시작하고, 상태는 열려 있는 페이지의 메모리에만 있어 같은 방문 안의 사이트 링크 이동에서만 유지된다.

- **2026 게임 표지 적용 (보류, 사용자 결정, 2026-11-09, T-217)**: Steam 상점 이미지를 표지로 쓰려던 결정을 보류했다. 게임사 허락 없는 사용이라 저작권 침해 가능성이 남고, 공개 저장소라 한 번 푸시하면 나중에 지워도 git 기록에 남기 때문이다. 지금은 표지 없이 이니셜 자리표시로 운영한다. 표지 기능(`cover` + `coverCredit`, 플레이 게임 페이지 아래 출처 목록)은 코드에 그대로 두므로, 나중에 허락된 이미지(직접 찍은 플레이 스크린샷, 이용 조건을 확인한 공식 프레스 킷 등)가 생기면 데이터만 넣으면 된다 (F013). Steam 상점 이미지는 쓰지 않으며, 다시 검토하려면 사용자 확인이 필요하다.
- **배경 음악 방식 (결정됨)**: 브라우저 자동 재생 정책 때문에 들어오자마자 재생은 하지 않고, 헤더의 음악 켜기/끄기 버튼으로 방문자가 켠다. 다시 방문하면 항상 꺼짐에서 시작한다 (켜짐 상태를 기억해 자동 재생을 시도하지 않음). 같은 방문 안에서 사이트 링크(클라이언트 이동)로 페이지를 옮길 때만 이어서 재생하고, 새로고침·새 탭·주소 직접 입력은 새 방문처럼 꺼짐에서 시작한다 (재생 위치 기억도 하지 않음). 음원은 운영자가 저작권 무료 음원(YouTube 오디오 보관함, Pixabay 등)을 골라 mp3로 저장소에 넣고, 출처·라이선스는 푸터에 표시한다. 음원이 없으면 버튼을 숨긴다. 음량 조절·재생 목록은 MVP 이후 (F015).
- **게임 기록 필드 (결정됨, 2026-11-09, T-209)**: `clearedAt`을 없애고 `endedAt`(끝낸 날, 클리어 여부와 관계없음, 선택)으로 바꿨다. 클리어하지 않고 그만둔 게임에도 끝낸 날짜가 있기 때문이다. `status`·`startedAt`·`endedAt`·`rating`·`comment`는 모두 선택이고, 상태가 없는 게임은 상태 배지 없이 표시한다. 표지는 `cover` + `coverCredit`(cover가 있으면 필수)으로 적는다. 모르는 필드가 있거나 `endedAt`이 `startedAt`보다 이르면 빌드 실패다.
- **UI 애니메이션 (결정됨)**: 첫 진입 연출(헤더 메뉴 스태거·홈 등장), 스크롤 등장, 페이지 전환(투명도), 카드·버튼 마이크로 인터랙션 4가지를 넣고, 라이브러리는 Motion(npm `motion`)으로 확정했다. 운영체제 "동작 줄이기" 설정을 따르고, 깔끔·짧게·레이아웃 흔들림 없이 만든다. 홈 히어로 타이핑·글리치 연출은 MVP 이후 (F016).

### 남은 확인 사항

- **Supabase 무료 플랜 한도**: 저장 용량과 전송량(egress) 한도를 넘으면 영상이 안 나올 수 있다. 영상은 압축(예: H.264 MP4, 1080p 이하)해서 올린다고 가정한다. 현재 무료 플랜 한도는 운영 전 확인한다.
- **MDX 라이브러리 (ROADMAP 단계 기술 확인)**: next-mdx-remote(RSC)를 제안했으나, Next.js 16·React 19 호환성은 ROADMAP 단계에서 확인한다. 안 되면 `@next/mdx` 또는 Velite 같은 빌드 시 콘텐츠 도구로 바꾼다.
- **simple-icons 사용 세부 (T-202·T-204에서 확인 완료)**: simple-icons 본체를 쓰고, 쓰는 아이콘은 모두 `license`가 없으며(브랜드 지침만), 아이콘이 없는 기술은 C#·Windows·VSCode·Visual Studio다.
- **기존 네온 스타일 정리**: 이미 구현된 neon-text 등 글로우 관련 스타일·클래스가 있다면 제거·교체가 필요하다 (소스 미확인, ROADMAP에서 작업으로 반영).
- **사진 경로와 basePath**: 사진은 `public/images/`에 두며, 나중에 `PAGES_BASE_PATH`를 쓰면 이미지 경로에 basePath를 붙이는 처리가 필요하다. 배경 음악 경로(`public/audio/`)도 같다.
- **첫 진입 연출의 범위**: 헤더 스태거는 페이지를 처음 불러올 때(첫 접속·새로고침)만 재생하고, 홈 등장 연출은 홈이 그려질 때마다(사이트 안에서 홈으로 돌아올 때 포함) 짧게 재생한다고 가정했다. 홈도 첫 진입에서만 보이게 바꿔도 된다.
- **페이지 전환의 "사라짐"**: App Router에서는 Motion의 퇴장 애니메이션이 안정적이지 않아, 기본은 새 페이지 본문이 투명도로 나타나는 효과로 구현한다고 가정했다. 이전 페이지가 흐려지는 크로스페이드는 React `<ViewTransition>`으로 검토하며, 프로젝트의 React 버전 지원 여부와 Motion과의 겹침은 ROADMAP 단계에서 확인한다 (문서 확인 필요).
- **JS 없이·느린 환경의 콘텐츠 표시**: 등장 효과는 처음에 투명도 0으로 그려지므로, 자바스크립트가 늦게 로드되면 잠깐 빈 화면이 보일 수 있다. 첫 화면(히어로·헤더)은 등장 거리를 작게, 지속 시간을 짧게 하고, 검색 엔진용 HTML에는 내용이 그대로 들어간다고 가정했다. 구현 시 확인한다.
- **카드 기울기 정도**: 호버 기울기는 마우스 위치를 따라 아주 작게(대략 수 도) 기울이고, 터치 기기에서는 기울기 없이 누름 효과만 쓴다고 가정했다.
- **음원 파일 크기·라이선스**: 한 곡을 반복 재생하는 짧은 루프 곡(예: 1~3분, 128kbps mp3, 수 MB 이하)을 가정했다. 저작자 표시가 필요한 라이선스면 `license`에 요구 문구를 그대로 적는다. 음원 선택과 라이선스 확인은 운영자 몫이다.
- **소개 데이터 형식**: 프로필·기술 스택·프로젝트·경력은 JSON 파일로 둔다고 가정했다 (TypeScript 상수 파일로 바꿔도 무방).
- **푸터 외부 링크**: 푸터는 `profile.json`의 `links`(GitHub, solved.ac 포함)를 써서 중복 입력을 피한다고 가정했다 (지금은 푸터가 `siteConfig`의 임시 값을 쓰고 있어 옮기는 작업이 남음).
- **프로젝트 섹션 (사용자 확인 필요, 2026-11-13)**: `projects.json`이 비어 있어 프로젝트 카드(F003의 일부)는 화면에 없다. 결정 전까지 가정: 보류(프로젝트가 생기면 다시 추가). 범위 밖으로 확정할지 사용자 확인이 필요하다.
- **게임 데이터 파일 구조**: 연도별 파일(`content/games/2026.json`)로 가정했다. 연도가 파일 이름에서 정해져 새해에는 파일 하나만 추가하면 된다. 단일 파일 + `year` 필드 방식으로 바꿔도 화면은 같다.
- **게임 기록 세부 규칙**: 평점은 1~5 정수(별 표시), 플레이 시간은 시간 단위, 플랫폼은 여러 개 허용, 그해 플레이한 게임을 그 연도 파일에 넣는다고 가정했다. 해를 넘겨 계속 플레이하는 게임은 다음 해 파일에도 같은 slug로 다시 적는다 (전체 보기에는 가장 최근 연도 것만 나옴).
- **상태가 없는 게임의 묶음 (T-211 계획 때 결정)**: `status`가 선택이 되어, 플레이 게임 페이지의 상태별 묶음(플레이 중 → 클리어 → 중단 → 하고 싶은 게임)과 상태별 게임 수 요약에서 상태 없는 게임을 어디에 둘지(예: 맨 뒤 "기타" 묶음) 정해야 한다. 결정 전까지 가정: 맨 뒤에 상태 이름 없는 별도 묶음으로 두고, 게임 수 요약에는 포함하지 않는다.
- **게임 데이터가 하나도 없을 때의 `/games` (T-218 가정, T-219 유지)**: `content/games/`에 파일이 하나도 없으면 `/games`가 "아직 기록한 게임이 없습니다" 안내만 보여 준다고 가정했다 (`/games/<연도>` 페이지는 생성하지 않음). `earlier.json`만 있으면 보기 목록은 "전체" 하나만 표시한다고 가정했다.
- **바 형태에서 평점·한 줄 소감 (T-220 가정)**: 결정된 한 줄 구성(이니셜·제목·상태·시간·날짜·플랫폼·▶ PV)에 평점과 한 줄 소감은 들어 있지 않다. 데이터 필드(`rating`, `comment`)는 그대로 두고, 화면 표시 여부는 T-220 구현을 기준으로 한다고 가정했다. 줄에 다시 넣을지는 사용자 확인이 필요하다.
- **전체 보기의 정렬·표시 (T-219 가정)**: 전체 보기도 연도 보기와 같은 상태별 묶음·정렬(시작일 최신순, 없으면 제목순)을 쓰고, 게임 줄에 연도 표시는 따로 넣지 않는다고 가정했다. 연도 표시가 필요하면 구현 계획 때 정한다.
- **PV 표시 방식 (T-218 가정, 2026-11-12 T-220 변경)**: PV가 있는 게임 줄은 오른쪽 ▶ PV 표시로 눌러 볼 수 있음을 알리고(이니셜 위 재생 아이콘 겹치기는 바 형태로 바뀌며 대체), 팝업은 16:9 비율로 화면 너비에 맞춘다고 가정했다. 영상 ID는 운영자가 게임사 공식 채널의 PV에서 골라 적는다.
- **코드 블록 언어 이름**: MDX 코드 블록에 언어를 적은 경우(예: ```` ```csharp ````)만 표시한다. 표시 이름 변환표(C#, C++, HLSL, GLSL, JSON 등)는 구현 시 정한다. 주요 하이라이트 언어(C#, C++, HLSL) 지원 여부는 ROADMAP 단계에서 shiki 언어 목록으로 확인한다.
